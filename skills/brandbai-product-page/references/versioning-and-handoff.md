# 设计、版本与下游交接

## 1. design

设计模式必须继承有效商品价值；推荐同时继承卖点呈现。先完成页面诊断，再把被确认的动作编译为主图序列或详情模块执行要求。

每个组件写明：当前功能、推荐功能、用户判断、调用价值/VIS、必须保留、可变化、所需素材和验收问题。不要输出最终视觉稿、虚构页面原文或把模板模块机械凑满。

## 2. route

页面路由从低成本到高成本判断：

1. **共用母版**：商品、SKU、价值和交易承接基本一致；
2. **入口适配**：共用事实与结构不变，只调整首屏或入口承接；
3. **动态/SKU适配**：按可确认 SKU、价格权益或人群条件替换局部模块；
4. **独立精细页**：只有入口差异、业务规模、证据和维护能力同时支持时才建立。

默认先用一套可维护的共用母版。入口、用户任务或商品版本不清时，不建议为了“精细化”直接复制多套页面。

## 3. version_review

至少提供两个真实页面版本，并严格标为 `current` 与 `comparison`；每版使用一个带时区的真实页面时间，并分别保留来源、页面范围和可读状态。两版必须至少有一个共同可读页面范围。比较时：

- 先检查商品、SKU、价格权益、流量范围和观察窗口是否可比；
- 分离页面变化、来源变化和下游交易变化；
- 记录只改了什么、共同保持什么和仍有哪些替代解释；
- 不可比时只输出差异，不判胜负；
- 有限历史结果不能写成未来效果承诺。

验证计划最多三条，每条的 `version_a/version_b` 必须绑定 `comparison/current`，只改一个主要变量，并写明必须保持、需要观察和停止条件。经营数据仍为可选；没有数据时只比较静态页面差异，不判胜负。课程模式不要求建立验证计划。

## 4. 上游变化

以下变化使当前页面判断评估为 `stale`；stale 结果只能留档，重新运行前不得作为当前正式交付：

- 商品、SKU或标准成交单元变化；
- 商品事实、P0/P1/P2或表达边界变化；
- 卖点呈现资产变为 blocked/stale；
- 新页面或包装与当前商品身份、规格或事实冲突；
- 动态权益已过期但旧页面仍作为当前版本使用。

旧版本保留，不覆盖；未变化的页面组件和动作保持稳定 ID。跨 SKU 必须新建运行。

## 5. 下游交接

视觉创作读取：页面组件执行要求、有效事实、VIS、必须保留、不可使用和验收问题；不得重新选择商品价值。

内容迁移或达人/直播任务可以读取页面如何承接商品与交易，但不能把页面排序直接复制成视频或直播顺序。

后续结果回写只能生成版本化候选：说明真实页面版本、内容/入口、观察窗口、可比条件、结果和替代解释。页面数据不能直接修改商品事实或自动升级 VIS。
