# 交付合同

## 1. 普通入口

### 01_商品页诊断与优化建议.md

固定包含：

1. 先看结论：一句话判断、页面现在主要靠什么卖、现有页面中建议继续保留的内容、最影响下单的问题和第一项开工项目；
2. 哪些信息还需要讲清：用“用户下单前，需要依次确认”“页面现在的讲述顺序”，以及至多三个“页面目前怎么讲＋不讲清会怎样”说明关键问题；
3. 改版后怎么讲：本轮目标、一个建议购买顺序，以及主图、交易区、详情页和页面最后确认各自承担什么；
4. 零至五项精简改版项目：要解决什么、具体怎么改、主要落点、需要准备、完成标准、保留内容；完整状态、调用依据与验证字段只留在 `data/`；
5. 认对、看懂、相信、选对、放心买五个问题压缩为“需要时再看”的一张复核表，只呈现页面已经讲清什么、还需要补什么和本轮安排；
6. 有可读详情页时，单列“详情页已有优势与提升空间”：优势说明其购买价值和保护要求，提升空间说明尚未讲清的内容、购买影响、优化方向和完成标准；
7. 本次商品、页面范围、页面时间与补充资料；
8. 还需补什么与使用边界：汇总改版前资料缺口、当前资料不能证明什么和长期表达边界。

品牌摘要必须先讲结论和动作，不能先让读者理解内部方法、状态枚举或数据结构。内部 ID、技术字段、哈希、脚本状态和逐文件清单只保留在 `data/`。

普通正文避免重复：整体问题只在结论区概括一次，详细页面观察留在结构化底稿；改版项目只在项目卡中完整展开一次，不再同时用“根因表、优先表、完整动作表”三次复述。五个购买判断是分析引擎和复核依据，不应抢占品牌报告主体。

结论区只展示一个“最影响下单的问题”；其余高影响问题在第二部分一次讲清。普通正文不得把“承接较弱、出现偏晚、证明衔接较弱、信息过载”等多组审计状态并排展示给品牌。页面现在的讲述顺序必须来自已观察页面节点，不能复用改版后的建议路线。

普通正文使用长期有效的优先级表达。除非用户明确给出排期，否则不得出现“明天、下周、首周、本月”等具体时间词；统一写“建议先做”“优先启动”“完成后”。

普通版统一使用品牌业务语言：可用输入写成“品牌内部商品资料”“可直接使用的卖点资料”或“页面公开信息”；后续动作写成“补充资料”“人工确认”或“上线后观察”。不得出现“商品价值上游”“卖点呈现上游”“返回上游”“商品价值底座”等内部工作流词；SKU、动态权益等字段词在普通报告中分别写成“商品选项”“当前优惠”。

业务语言不是逐词替换。遇到“SKU映射、跨SKU一致性、证据链、动态权益分区”等内部表达时，必须按整句重写为品牌能直接理解的问题或动作，例如“不同商品选项混用了同一组内容”“每个商品选项要对应自己的主图和证明资料”；不得保留替换后语法不通的病句。

### 02_主图交易区详情页优化页纲.md

正文标题使用“商品页改版执行方案”。先给出本次怎么改、改版项目顺序和各页面位置的职责，再分别展开：

- 主图按张序列出主要任务、具体改法、所需素材和完成标准；
- 交易区必须输出可执行选择卡：用户要决定什么、当前页面怎么写、新版怎么组织、当前所选怎么标、实际到手与当前优惠怎么说明、还需准备什么和完成标准；
- 交易区把长期商品信息与价格、赠品、库存、物流等发布前更新信息分别呈现；
- 详情页不按旧图张序给建议，而是输出整页任务、新版讲述路线、内容地图和现有素材迁移；
- 详情页每个内容章节必须写明用户问题、页面答案、必含内容、可用现有内容、呈现方向、待补资料和完成标准；
- 所有旧详情内容都必须在新版安排表中得到继续使用、集中呈现、分别进入不同章节、调序、本轮不使用或确认后再安排的明确去向。

版本比较统一写成“上线后怎么判断是否有效”，不用“验证任务、单一变量、可比条件”等研究口吻作为一级表达。

它是整体重构策略的执行页纲，不是最终设计稿或整套成品文案。主图逐张任务只是落地层，不能替代整体诊断；详情页章节不是详情图张数，页面不需要的模块不得为了模板完整而补齐。

课程模式可只输出 `01`；专业模式固定输出 `01` 与 `02` 两份。资料缺口与证明边界合并在 `01`，不再默认生成第三份文档。医疗器械、婴幼儿食品等高风险商品只有在用户明确需要时才另行整理证据附件；附件必须来自同一 `data/` 底稿，不得改变主报告结论。

## 2. 动作标签

每项动作只使用一个主标签：

| 标签 | 允许进入页纲 | 含义 |
| --- | --- | --- |
| 可直接优化 | 是 | 不新增资料外主张，可立即调整结构、顺序或已确认表达 |
| 补充资料后优化 | 条件式 | 先补事实、证据、素材或授权，再进入正式改版 |
| 待上线验证 | 是 | 可执行但效果未知，写明上线观察问题 |
| 不建议使用 | 否 | 证据越界、跨SKU、过期、误导或无法兑现 |

动作类型仍只使用：`保留／删除／补充／前移／重新组织／人工核实`。

每条动作都必须填写且只填写一个上述建议标签；空白标签或自定义标签均不构成正式交付。

## 3. 正式交付门槛

- 只处理一个页面主讲成交单元和一个页面版本；
- 页面主讲 SKU 必须能在交易区可见选项中确认；
- 无法明确归属于页面主讲 SKU 的动态交易快照不得进入正式动作；
- 至少一份页面材料已视觉读取，否则停止且零动作；
- 当前 SKU 不明时，不输出会改变卖点或证据的正式动作；
- 非停止状态固定完成五个购买判断，不生成总分；
- 非停止状态至少建立两项有顺序、有依据、有边界的细分类目购买任务；只有页面材料时，成熟度不得高于工作假设；
- 非停止状态必须建立 `detail_page_plan`；详情页不在范围内写 `not_in_scope`，没有可读详情页写 `insufficient_material`；
- 非停止状态必须检查交易区并建立 `transaction_panel_plan`，但不强制修改；只有交易区妨碍用户选对或确认到手时才形成一个主要规格选择区改版方案，已经清楚时必须标为 `preserve_only` 且不生成选择区改版卡；正式方案只保留平台当前结构可以实施的建议；
- 有可读详情页时必须建立 `detail_page_assessment`，不得只列问题或只列优点；没有可读详情页时必须明确资料不足，不得推测；
- 有可读详情页时必须形成连续内容地图，并用素材迁移表完整覆盖全部详情内容节点；普通版不得重新输出旧详情图逐张建议；
- 每个细分类目任务在双链匹配账本中恰好出现一次；每个页面内容节点至少关联一项细分类目任务；
- 双链匹配必须分别判断承接、位置、证据连接与重复／过载，不能只写“有／没有”；
- 五个判断不得只写状态或笼统摘要，必须拆出已讲清、还没讲清、购买影响和具体补法；
- 非“保留”动作不得绑定状态为“已讲清”的购买判断；
- 页面当前主张与已确认事实分开；
- 增强资料逐项记录适用 SKU、能证明和不能证明；
- 整体根因最多三项，必须说明页面依据、购买后果与受影响判断；
- 页面改版项目总数不超过五项，依据不足可以为零；
- 每个改版项目必须有一个非空且合法的建议标签；
- 除“保留”外，每个改版项目必须绑定至少一个整体根因；
- 除“保留”外，每个改版项目还必须绑定至少一个仍有双链断点的细分类目任务；完全匹配的任务只能保留；
- 每项动作绑定页面位置和可读来源；
- 页面已有结构调整可以只用页面可见依据，新主张必须调用可用补充证据；
- 评论只作为用户信号，竞品只作为结构／表达观察；
- 动态权益有时间，过期或时间未知时只进入人工核实；
- 其他变体、套组单品、关联商品和品牌共性不证明当前 SKU；
- 普通版无内部 ID、本地绝对路径、技术字段或模板占位符；
- 普通版不得披露或评价页面采集、下载和误选过程；
- 普通版不得把改版后建议路线写成页面现在的讲述顺序，也不得出现“这类商品用户通常如此”等超出成熟度的用户共识表达；
- 普通版不得出现“本次先按这条购买顺序检查、最大购买断点、完整判断依据”等内部审查口吻；
- 两份普通文件使用同一底稿，不出现事实、优先级和边界漂移；
- 所有动作均不承诺点击、转化、GMV、ROI 或销量提升；
- 校验退出码为零。

正式通过只表示本次静态诊断、证据和交付结构完整，不表示页面已经有效、视觉稿已发布或改版产生经营结果。
