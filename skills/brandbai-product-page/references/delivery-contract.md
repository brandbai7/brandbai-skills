# 交付合同

## 1. 普通入口

### 01_商品页诊断与优化建议.md

固定包含：

1. 页面整体诊断：当前成交策略、核心购买理由、专业判断与已经做对并应保留的部分；
2. 至多三个整体根因：页面依据、购买后果和受影响的购买判断；
3. 整体优化与重构思路：本轮目标、新版购买逻辑、连续叙事路线，以及主图、交易区、详情页和决策收口的分工；
4. 认对、看懂、相信、选对、放心买五个判断，并分别展示已讲清、还没讲清、购买影响和具体补法；
5. 零至五项完整改版项目及四类建议标签；除“保留”外，每项必须对应至少一个整体根因；
6. 本次商品、页面范围、页面时间、可读范围与证据成熟度；
7. 第一项开工项目、本轮暂不做和结果边界。

品牌摘要必须先讲结论和动作，不能先让读者理解内部方法、状态枚举或数据结构。内部 ID、技术字段、哈希、脚本状态和逐文件清单只保留在 `data/`。

普通版统一使用品牌业务语言：可用输入写成“品牌内部商品资料”“已验证卖点资产”或“页面公开信息”；后续动作写成“补充资料”“人工确认”或“上线验证”。不得出现“商品价值上游”“卖点呈现上游”“返回上游”等内部工作流词。

### 02_主图交易区详情页优化页纲.md

先给出新版页面内容架构、改版项目顺序和各页面表面的职责，再按实际页面顺序列出：区域／张序、当前任务、建议任务、主要决策、动作、建议表达、所需素材、必须保留、禁用表达、负责人和验收问题。

它是整体重构策略的执行页纲，不是最终设计稿或整套成品文案。逐图建议只是落地层，不能替代整体诊断；页面不需要的模块不得为了模板完整而补齐。

### 03_资料缺口与证据边界.md

分为：可直接调用资料、补充后可调用资料、动态快照、待人工核实、禁止扩写、后续可选资料。必须明确“当前资料能证明什么／不能证明什么”。

课程模式可只输出 `01`；专业模式固定输出三份。

## 2. 动作标签

每项动作只使用一个主标签：

| 标签 | 允许进入页纲 | 含义 |
| --- | --- | --- |
| 可直接优化 | 是 | 不新增资料外主张，可立即调整结构、顺序或已确认表达 |
| 补充资料后优化 | 条件式 | 先补事实、证据、素材或授权，再进入正式改版 |
| 待上线验证 | 是 | 可执行但效果未知，写明上线观察问题 |
| 不建议使用 | 否 | 证据越界、跨SKU、过期、误导或无法兑现 |

动作类型仍只使用：`保留／删除／补充／前移／重新组织／人工核实`。

每条动作都必须填写且只填写一个上述建议标签；空白标签或自定义标签均不构成正式交付。

## 3. 正式交付门槛

- 只处理一个页面主讲成交单元和一个页面版本；
- 页面主讲 SKU 必须能在交易区可见选项中确认；
- 无法明确归属于页面主讲 SKU 的动态交易快照不得进入正式动作；
- 至少一份页面材料已视觉读取，否则停止且零动作；
- 当前 SKU 不明时，不输出会改变卖点或证据的正式动作；
- 非停止状态固定完成五个购买判断，不生成总分；
- 五个判断不得只写状态或笼统摘要，必须拆出已讲清、还没讲清、购买影响和具体补法；
- 非“保留”动作不得绑定状态为“已讲清”的购买判断；
- 页面当前主张与已确认事实分开；
- 增强资料逐项记录适用 SKU、能证明和不能证明；
- 整体根因最多三项，必须说明页面依据、购买后果与受影响判断；
- 页面改版项目总数不超过五项，依据不足可以为零；
- 每个改版项目必须有一个非空且合法的建议标签；
- 除“保留”外，每个改版项目必须绑定至少一个整体根因；
- 每项动作绑定页面位置和可读来源；
- 页面已有结构调整可以只用页面可见依据，新主张必须调用可用补充证据；
- 评论只作为用户信号，竞品只作为结构／表达观察；
- 动态权益有时间，过期或时间未知时只进入人工核实；
- 其他变体、套组单品、关联商品和品牌共性不证明当前 SKU；
- 普通版无内部 ID、本地绝对路径、技术字段或模板占位符；
- 普通版不得披露或评价页面采集、下载和误选过程；
- 三份普通文件使用同一底稿，不出现事实、优先级和边界漂移；
- 所有动作均不承诺点击、转化、GMV、ROI 或销量提升；
- 校验退出码为零。

正式通过只表示本次静态诊断、证据和交付结构完整，不表示页面已经有效、视觉稿已发布或改版产生经营结果。
