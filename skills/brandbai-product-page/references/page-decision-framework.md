# 商品页五个用户判断

## 0. 整体先于局部

先把商品页当成一套完整的成交叙事，而不是图片清单。开始逐图检查前，必须先回答：

1. 当前页面采用什么成交策略，想靠什么让用户购买；
2. 页面已经做对什么，哪些能力应被保留；
3. 最多三个整体根因是什么，它们如何影响购买；
4. 新版页面应建立怎样的购买逻辑，主图、交易区、详情页和决策收口分别承担什么。

逐图和逐模块观察只用于支持整体判断、定位落点与形成执行清单。除“保留”外，任何改版动作都必须回指至少一个整体根因，不能因为某张图“还可以更好”就独立立项。

## 1. 先判断页面当前的一核

先用一句话写清页面当前最希望用户记住并据此购买的理由。只用现有页面时，必须称为“页面当前核心购买理由／页面当前主张”，不能称为已确认商品价值。

检查它是否：

- 对应当前商品和当前 SKU／套组；
- 能被用户理解为具体利益、体验、任务或选择理由；
- 在主图、交易区和详情页之间保持一致；
- 有相邻事实、证据或明确的待核实标记；
- 没有被活动、明星、榜单、赠品或次要卖点挤掉。

补充资料后，只有来源、适用对象和边界明确的内容才能升级为正式页面依据。

## 2. 再看用户是否能完成判断

商品页不是卖点堆叠表。依次检查：

1. **认对**：商品、品牌、SKU、规格、数量和实际到手是否不会认错；
2. **看懂**：用户能否用自己的话理解核心价值、利益和差异；
3. **相信**：事实、演示、证据、边界与页面主张是否能互相支撑；
4. **选对**：不同 SKU、适用对象、场景、用法和选择关系是否清楚；
5. **放心买**：价格权益、库存、物流、售后、风险提示和交易承接是否清楚且没有过期冒充当前。

每项只用“已讲清、部分讲清、未讲清、资料不足”。不要做没有基准的综合评分。

状态不是诊断结果本身。每项必须继续拆成四句：

1. **已讲清**：页面已经帮助消费者完成了什么；
2. **还没讲清**：仍缺哪项关键信息，或哪处表达造成冲突；
3. **购买影响**：消费者因此会犹豫、误选、误解还是不信；
4. **具体补法**：保留什么、补什么、前移什么或删掉什么。

只有“还没讲清”的部分进入优先动作。状态为“已讲清”且没有关键缺口时，只记录保留要求，不占零至五项优化动作。

使用“够用即可”原则判断缺口：信息在消费者做决定前已经由合适页面位置承接，就不要求每个页面表面重复。首图负责快速认出与建立一个主要购买理由，不必强制写入总克重、全部参数、检测小字和所有限制；这些内容由交易区或详情页清楚承接时，不算首图缺失。不要把“可以进一步完善”都升级成“阻断购买”。

规格判断必须分两层记录：第一层是平台原始规格组和当前选项，第二层是用户真实要完成的选择任务。平台字段名只是界面容器，不能直接当成用户决策维度；例如“颜色分类”可能同时混入配方、色号、限定包装和容量，“口味”可能同时混入口味、数量、组合和包装版本。

## 3. 主图检查

首图和主图序列不是把详情页压缩成几张海报。逐张记录当前功能，再检查序列是否完成：

- 首图先让用户认对商品和 SKU；
- 前部尽快承接已确认核心价值，不重新选择价值；
- 中部用可见、可听或可核对的事实和 VIS 建立相信；
- 后部解释规格、适用、用法、选择与交易信息；
- 每张图只有一个主要判断任务，必要信息可以辅助但不抢主任务；
- 重复表达必须说明重复的功能价值，否则作为候选压缩项；
- 小字不可读、顺序未知或来源缺失时保留未知，不补全。

“把场景图放首图”“把参数放第二张”都不是通用答案。位置由用户判断、上游价值、事实确定性和平台限制共同决定。

## 4. 交易区检查

交易区先承担“可成交性核对”，再承担“当前快照读取”：

- 先识别页面主讲 SKU 是否出现在可见选项中；
- 再确认当前可见价格、权益、赠品、库存和到手信息是否明确归属于页面主讲 SKU；
- 无法确认归属的动态交易信息只记录为待核实，不迁移到页面主讲 SKU；
- 页面主讲 SKU 不在可见选项中，或页面由多个 SKU 混合且无主讲对象时，停止正式动作；
- 用户明确确认目标 SKU 仍可成交时可以继续，但把确认人和边界写入底稿。

随后检查平台原始规格组、真实选择维度、套组构成、目标 SKU 的价格／权益条件、赠品、实际到手、物流和必要售后。说明入口、服务入口、关联商品和占位项不能一律当作真实 SKU。

## 5. 详情页检查

按功能模块而不是固定模板检查：

- 商品与 SKU 身份；
- 核心价值与用户任务；
- 价值如何被感知；
- 事实、机制、演示和证据；
- 适用对象、场景、用法与限制；
- SKU/规格/数量/实际到手；
- 价格权益、物流、售后和风险提示；
- 行动承接。

模块可以合并或调序，但不得因为页面篇幅强行凑齐。页面未提供的部分先写未知；只有完整可读页面才能判断“确实缺失”。

## 6. combined 的跨触点检查

主图与详情页一起看时，至少检查：

- 页面主讲 SKU 是否可成交，当前可见交易信息是否明确归属于它；
- 商品、页面主讲 SKU、规格和数量是否一致；
- 首图承诺是否能在详情页找到事实或边界；
- 核心价值是否一致，是否被次要信息抢走；
- 证据是否服务同一主张，是否跨 SKU 或过期；
- 动态权益和实际到手是否一致；
- 主图建立的预期是否被详情页继续承接。

combined 是一次共同排序，优先动作总数最多五项。

## 7. 证据差异的相关性判断

检测、认证、专利或报告与当前 SKU 有字段差异时，不按“数字不同＝证据无效”处理，依次判断：

1. 样品是否仍是同一商品、同一配方／原料、同一产品形态与同一生产主体；
2. 差异字段是否正是本次检测或证明的对象；
3. 结果是按单位、成分或污染物水平表达，还是按整包装总量表达；
4. 最终把证据标为当前 SKU 直接证据、当前商品参考、系列级参考、适用范围待确认或不可用。

包装总克重、罐数和包装版式不同，本身不等于检测结论失效。例如，同配方商品的污染物或微生物检测通常不会仅因整盒400克与500克而自动失效；但净含量检测、单罐克重或整盒数量结论会直接受影响。只有差异与被证明结论相关，或产品身份、配方、原料、产品形态、型号、适用对象、生产主体发生实质变化时，才升级为证据错位。

## 8. 优先级

先把候选问题收敛为最多三个整体根因，再按三个条件排序改版项目：

1. **用户判断重要性**：是否阻断认对、看懂、相信、选对或放心买；
2. **证据确定性**：页面观察和上游事实是否足够确定；
3. **本轮可执行性**：是否有素材、权限和人工确认条件。

高影响但证据不足的事项进入缺口或人工核实，不强行变成确定动作。改版项目可以少于五项，也可以是零项；除“保留”外必须回指整体根因。

## 9. 事实和信号分层

- 上游商品事实：可用于正式动作，但继续继承适用范围和不能证明什么；
- 页面可见表达：只能证明页面这样说或这样展示；
- 用户评论/问答：只能形成特定样本范围内的顾虑或语言信号，不能裁定商品事实；
- 经营数据：只能按页面版本、时间窗、口径和可比条件形成观察；
- 推导：标为待验证解释；
- 未知：保持未知，不转成“没有”或零。
