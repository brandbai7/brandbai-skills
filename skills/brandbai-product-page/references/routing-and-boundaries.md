# 路由与能力边界

## 1. 任务路由

| 用户任务 | 处理方式 |
| --- | --- |
| 下载主图、详情、视频、参数、评价或问大家 | 下载助手或对应下载 Skill |
| 基于现有页面找问题并给优先动作 | `diagnose_existing` |
| 补充商品／证据／用户／业务资料后深化页面方案 | `enhance_with_evidence` |
| 建立完整商品事实、FABE、P0/P1/P2底座 | 可选 `brandbai-product-value`，不作为本 Skill 强制前置 |
| 把价值编译为视频、直播或达人动作资产 | `brandbai-value-expression` 或后续内容能力，不在本 Skill 自动执行 |
| 生成最终视觉稿、上传或发布页面 | 独立设计／发布流程 |

## 2. 结论权限

| 可用输入 | 允许结论 |
| --- | --- |
| 部分页面截图 | 仅对可读范围做静态观察，未知保留 |
| 完整页面 | 判断页面当前一核、五决策、顺序、重复、冲突和到手承接 |
| 页面＋补充事实／证据 | 形成可调用的新模块或表达建议，并继承证据边界 |
| 页面＋用户信号 | 形成顾虑、语言和场景候选，不裁定商品功效 |
| 页面＋竞品页面 | 比较结构和表达，不裁定本商品优势 |
| 两个真实页面版本＋可比数据 | 形成有边界的版本观察，不自动归因 |

## 3. 运行状态

- `ready`：页面可读、当前成交单元明确，正式动作均有足够页面或补充证据；
- `partial`：页面只读到部分范围、SKU／套组仍需确认，或部分建议等待补充资料；只对可读范围给条件式动作；
- `degraded_no_product_value`：兼容旧结构的内部状态；在 `diagnose_existing` 中表示“仅依据当前页面诊断”，不是失败，也不要求先安装其他 Skill；
- `stopped`：没有任何可读页面、当前成交单元无法隔离、资料严重冲突，或用户要求编造事实／证据。动作必须为零。

## 4. 永久边界

- 页面出现不等于表达有效或事实成立；
- 评论出现不等于用户普遍认知；
- 高销量不等于页面结构造成销量；
- 整体数据变化不等于某张图或某个模块造成；
- 历史版本表现不等于未来表现；
- 公开页面主张不等于第三方独立验证；
- 静态建议不等于最终视觉稿、合规审核或发布通过。
