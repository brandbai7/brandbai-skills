# 路由与能力边界

## 1. 先判断用户要做什么

| 用户任务 | 路由 |
| --- | --- |
| 下载主图、详情图、视频、参数、评价或问大家 | 下载助手或对应下载 Skill |
| 从商品页、包装和资料建立事实、FABE、P0/P1/P2 | `brandbai-product-value` |
| 把已确认价值翻译成画面、动作、声音、字幕和道具 | `brandbai-value-expression` |
| 检查价值与呈现有没有在主图/详情页被正确承接 | 本 Skill |
| 生成最终视觉稿或图片成品 | 独立视觉创作或设计能力 |
| 生成短视频、达人内容或直播话术 | 后续内容组装或迁移 Skill |

“详情页”既可能是商品价值的资料源，也可能是本 Skill 的待诊断对象。先按用户意图分流，不能把两个任务合并后在页面诊断中重做 P0。

## 2. 四种运行状态

### ready

SKU明确、页面可读、P0已进入选择、验证或边界已验证状态，且至少一个卖点呈现资产可用。可以给零至五项正式动作。

### partial

商品价值可用，但页面只读到部分范围、卖点呈现缺失、部分动态信息未知，或P0仍是有边界的待验证假设。只对可读范围给零至五项动作，必须继承限制。沿P0假设形成的动作只能写成有条件建议，不能声称该价值已被品牌选定、被用户验证或具有竞争优势。

### degraded_no_product_value

没有可用商品价值，或提供的商品价值属于其他 SKU、已失效、P0已重开／替换／停止。仍可做页面表面检查，但最多三项低风险动作：

- 讲清商品、SKU、规格、数量和实际到手；
- 标记同一页面内可见冲突、不可读、重复或缺失范围；
- 对功效、数字、价格、权益和时效提出人工核实；
- 列出继续分析需要的资料。

此状态不得决定主卖点、价值层级、核心证据或详情页说服顺序，必须建议返回商品价值 Skill。

### stopped

SKU无法隔离、没有任何可读页面、文件损坏，或用户要求编造事实/证据。优先动作必须为零，只说明停止原因、缺口和下一步。

## 3. 输入权限与结论权限

| 可用输入 | 允许结论 |
| --- | --- |
| 只有部分截图 | 静态表面观察、可读范围和未知 |
| 页面＋有效商品价值 | 正式页面判断与优先动作 |
| 再加卖点呈现 | 具体位置、顺序和执行要求 |
| 再加两个真实页面版本 | 有边界的版本差异与验证计划 |
| 再加可比经营数据 | 指定条件下的观察，不自动形成因果 |

证据减少时结论只能变弱，未知只能增加。旧版本结果不得跨 SKU 或跨页面版本自动继承。

## 4. 永久禁止

- 页面出现不等于表达有效；
- 评论出现不等于用户普遍认知；
- 整体数据变化不等于某张主图或某个模块造成；
- 历史版本表现不等于未来必然表现；
- 公开页面主张不等于第三方独立验证；
- 设计建议不等于最终视觉稿或发布审核通过。
