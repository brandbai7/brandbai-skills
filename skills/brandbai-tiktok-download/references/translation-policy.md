# TikTok 中英翻译策略

## 产品目标

把多国家 TikTok 内容转成可回溯的双语研究材料。任何译文都必须与原文并列，不覆盖原文，不把机器翻译当成达人原话或用户原话。

默认目标语言为中文 `zh` 和英文 `en`：

- 原文为中文：中文列保留原文，只生成英文译文。
- 原文为英文：英文列保留原文，只生成中文译文。
- 原文为其他语言：分别生成中文和英文译文。
- 纯表情、纯链接、纯数字、用户名和无自然语言内容：保留原文，标记 `skipped_nonlinguistic`。

## 首批适用场景

1. 发布文案、标题和正文：用于快速理解达人内容主题、产品表达和行动号召。
2. 一级评论：用于跨国家读取用户反馈、疑问、使用体验和争议；译文只作为理解辅助。
3. Excel 交付：作品清单和评论明细增加双语字段，供后续达人分析 Skill 同时读取原文与译文。
4. 搜索快照：翻译已经采集到的卡片标题；关键词的多语扩展属于后续“发现”能力，不与下载结果混写。

暂不把以下能力混入免费文本翻译：视频语音转写、语音翻译、视频画面 OCR、字幕时间轴生成、配音和字幕烧录。

## 免费本机路线

在 Chrome 138+ 桌面版中，先检测 `LanguageDetector` 与 `Translator`：

1. 由用户点击“生成中英译文”，满足首次模型创建需要的用户操作条件。
2. 先做能力检测，并在本次用户点击产生的可见页面上下文中调用 `LanguageDetector.create()` 识别源语言。
3. 置信度不足时保留 `unknown`；短词、俚语或表情评论不得强行判断语言。
4. 针对需要的语言对调用 `Translator.create()`；需要下载模型时展示语言包进度。
5. 在可见的侧栏或扩展页面中顺序执行翻译并显示进度。Translator API 不在 Web Worker 中运行，因此不要把任务放进 Manifest V3 service worker。
6. 对同一原文、源语言、目标语言和翻译引擎版本生成稳定缓存键，避免重复翻译。
7. 浏览器不支持、语言对不可用、模型下载失败或用户关闭页面时，保留原文并写明失败状态，不自动切换云端计费。

本机路线不向 BrandBAI 或第三方服务器上传文本，不消耗云端字符额度，但会在首次使用时下载浏览器语言包，并可能占用本机时间和存储。

## 云端与计量路线

只有用户明确开启云端回退并已登录有额度的 BrandBAI 账号时才调用服务端。公开扩展只能调用 BrandBAI 后端，第三方服务密钥必须保存在服务端。

分别记录三种原始计量单位，不要先混成不透明的单一次数：

- 文本翻译：输入字符数、目标语言数、缓存命中数。
- 语音转写／翻译：实际处理音频秒数。
- OCR：实际处理图片数或抽帧数。

计量日志至少包含 `operation_id`、功能、来源对象 ID、输入单位、目标语言、提供方、模型版本、预计消耗、实际消耗、缓存命中、结果状态和时间。失败请求是否扣量按提供方真实账单回写，不能按前端点击次数扣量。

## 导出字段

作品文案和评论统一保留：

- `source_text`：原文。
- `detected_language`：BCP 47 源语言或 `unknown`。
- `language_confidence`：语言检测置信度；不可用时留空。
- `translation_zh`：中文译文或中文原文。
- `translation_en`：英文译文或英文原文。
- `translation_status`：当前本机版使用 `translated_local`、`translated_local_low_confidence`、`skipped_nonlinguistic`、`language_undetermined`、`partial_translation`、`translation_failed`、`not_generated`。
- `translation_engine`：当前本机版为 `chrome_local_v1`；未生成时留空。
- `translation_generated_at`：译文生成时间。

译文不得进入原文列，不得改写原始话题、@用户名、链接、品牌名、型号和表情。分析时优先引用原文，并把译文标注为机器翻译。

## 上线顺序

1. 免费：单作品发布文案中英双语导出。
2. 免费：已采集一级评论中英双语导出，提供进度和缓存。
3. 免费：达人主页和搜索结果当前可见作品文案批量翻译；默认不自动开启，避免无意等待。
4. 付费：云端文本回退和大批量加速。
5. 付费：语音转写后再翻译。
6. 付费：OCR、字幕时间轴、配音等创作能力。
