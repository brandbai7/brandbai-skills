# 本地视频字幕与可选画面（v0.6.6 试用版 / v201）

本版采用与 v201 同步的冻结运行时，不自动替换已安装版本。自动检测默认保守单帧，使用一个独立单线程识别工作进程；双帧仅保留为内部显式测试，不是默认或命令行选项。固定区域与新自动检测入口必须明确择一，不忽略用户已确认的区域。运行时清单保留原候选快照的 schema 与资源 SHA，不因公开试用版号而改写历史身份。

Skill 包版本为 `0.6.6`；冻结适配器回执继续记录 `wrapperVersion=0.6.6-candidate`、`releaseStatus=candidate_not_accepted`。后者表示识别运行时尚未完成全面质量验收，不是 GitHub 上传状态，也不因发布试用附件而升级为已验收。两层版本分别保留，不重写旧结果。

## 使用边界

- 只有明确请求字幕时运行，下载作品不默认触发。
- 处理已下载的一个视频：不上传、不调用语音识别，不增加平台浏览动作；不是“发布文案”。
- 单视频限 180 秒、150 MB。旧区域模式只支持固定单行；新自动模式检测原生画面的文字行，以位置、时间与样式识别字幕候选及其他文字。不是所有画面文字都属于字幕，也不承诺完整复杂花字或所有动态排版。
- 按 0.5 秒采样。快速闪现的字幕可能漏掉；画面里的标题、水印、包装文字也可能混入。
- 本地模型的实际名称、版本和 SHA-256 见随包 `vendor/manifest.json` 与每次结果的 `runtime`。模型有识别误差；`processed` 只表示采样流程结束，`accuracy=machine_unverified` 必须保留。不得把置信分数当作实测准确率。
- 对连续相同或有可靠多帧支持的近似句自动保守整理，保留原始候选。数字、单位、否定词、身份信息和隔开后再出现的句子不得粗暴合并；不使用语言模型改写或猜正确字，不伪造人工核验。
- 极低可信的首尾增字只在同一区间有可靠原图完整句支持时做可恢复整理；代表句必须是实际识别过的句子。`observations`、每段 `candidates` 和适用时的 `retainedSegments` 保留在 JSON，可回查并恢复原分段；TXT 是便于工作的整理视图，不应单独取代原记录。繁简字形与复杂背景文字仍可能有误。
- Windows Chrome 是当前本地验证环境；其他系统使用 `--chrome-path` 指定浏览器，尚未实机验收。不自动安装依赖、浏览器或下载模型。

## 自动逐行检测与工作包（试用入口）

依赖 Python、Playwright 与本机 Chrome。模型与共享模块随包位于 `assets/subtitles-native/`，无需用户上传已下载视频。默认使用 PP-OCRv4 检测、PP-OCRv5 移动识字、PP-OCRv6 medium 精读与 OpenCC 简体转换；以 `runtime-manifest.json` 和每次结果记录的实际 SHA 为准，不根据模型命名宣称准确率。

```powershell
python scripts/extract_video_subtitles.py `
  --video-file "<已下载的单个短视频.mp4>" `
  --out "<新的字幕输出目录>" `
  --detected-lines `
  --dry-run
```

核对文件 SHA、模式和随包资源后去掉 `--dry-run`。不能同时传 `--region`。若下载记录已确认作品 ID，可增加 `--work-id`；不要从文件名猜 ID。默认模型处理时限 1200 秒，可用 `--deadline-seconds` 明确调整（60—1800）；超时保留原记录，不记为成功，不重复启动仍在运行的任务。

自动检测默认 `captureMode=text_only`，不建立配图收集器、不编码 JPEG、不生成图文画廊；只省去配图处理，检测、移动识字、精读、采样和原始证据规则全部沿用共享 v201。需要逐句画面时在同一命令显式增加 `--with-frames`，记录为 `captureMode=with_frames`。该开关不能用于旧 `--region` 模式。

### 扫描调度与资源记录

auto 策略在新任务创建时只解析一次，任何硬件预算均默认 `capacity=1`，原因记录为 `serial_baseline_parallel_benefit_not_established`。浏览器 `hardwareConcurrency` 与 `deviceMemory` 只作诊断；内存值是粗略总内存提示，不是当前可用内存，不能当作性能保证。有限双帧调度只接受内部明确数值 `2` 的测试覆盖，不对用户提供并行开关、不自动启用。每个进程只有一个模型计算线程；取帧、视频定位保持串行，同一进程不重叠读取，原生帧和裁剪来源校验不变，提交按原观察顺序进行。所有模型与精读规则不变。

结果中的 `scanScheduling` 保存请求策略、实际选择、原因和硬件观察；`runtimeTiming.scanQueue` 保存实际创建进程数、并发峰值、取帧及提交计数等。初始化失败按原有边界停止并保留部分记录，不自动降级重跑。暂停、取消和资源清理沿用已冻结的队列合同。

精读恢复记录 `capacity=1`、`scanApplicable=false`，只补合法精读或扩框待办，不重复扫描检测或移动识字；既有原帧和裁剪身份验证仍执行。已完成识别结果、原始候选、简体工作稿、独立疑点和采样时间口径均保留。单片对照结果不代表所有视频质量或所有机器性能已经验收。

默认纯文本模式生成以下工作结果：

- `视频字幕.txt`：带采样观察时间范围的工作稿；`字幕正文.txt`：便于整理脚本的正文。正文保留当前选定实际原读，疑点独立保存，不插入机器候选提示；不代表完整口播、精确字幕轴或人工核验。
- `字幕疑点.txt`：只在存在疑点时生成。真实不同识别结果与来源校验未完成分开说明；保留全部实际不同读数，不把技术状态写成文字分歧。
- `待确认字幕候选.txt`：存在待确认文字时单独生成。这些实际读数可能是短暂字幕、强调字或其他画面文字；正文 TXT 与复制稿不自动混入此层内容。
- `机器分段.csv`：素材编目、脚本整理与剪辑定位，不自动添加商业分析。
- `字幕识别记录.json`：原生帧、行框、模型原始读数、简体处理、分段、工作稿容器、候选与关键分歧，包含输入身份、实际资源 SHA 与完成状态。
- `字幕工作包.zip`：上述纯文本资料的便携副本，不包含原视频或浏览器资料；未请求配图不记为丢图。

使用 `--with-frames` 时，另生成 `逐句图文.html` / `逐句图文.md`、`逐句配图.csv`、`配图清单.json` 与 `画面/`，ZIP 名为 `字幕画面工作包.zip`。正文候选及待确认文字各自绑定真实画面，后者不自动升为正文；长句内明显画面变化可保留多张。模型只读原生像素，不把 JPEG 当识字输入。真实丢图明确记录，不用另一句图片补齐。

工作稿统一为简体中文，原始读数保留。连续完整相同读数可整理为一个工作容器，不删除原子事件；受限的标点与非关键首尾差异保留为“未确定的不同读数候选”。数字、单位、否定、姓名、商品名称与中间实义字差异不得按整句相似度猜并；相隔重现的句子不全局删除。没有语言模型、字典或参考答案改写，不以多帧高分冒充人工核实。

原片 SHA 在宿主和浏览器分别核验，结束时再次核验文件与模块；每图记录自身帧、时间与原生像素身份。`processed` 只是流程结束，`accuracy=machine_unverified` 必须保留。输出目录必须为空，不能覆盖旧资料。进度检查点用于审计，不自动重启任务；中断后先确认原任务已结束。

### 限定续跑精读或扩展精读

只有自动模式已完成全部采样、保留完整原生帧与行归属，停在 `precision` 或 `extent_precision` 且仍有严格有效待办时，才可在新空目录补完。`precision` 要求原始顺序的已读前缀与待办后缀恰好组成全部非屏幕文字事件；已完成读数、原图校准及角色归属必须完整。`extent_precision` 仍要求代表精读全部完成。失败队列、身份或资源变化、其他阶段和任意历史记录不能强制续跑。

```powershell
python scripts/extract_video_subtitles.py `
  --video-file "<同一个原视频.mp4>" `
  --out "<新的恢复输出目录>" `
  --detected-lines `
  --resume-record "<原字幕识别记录.json>" `
  --resume-record-sha256 "<实际计算并固定的原记录SHA256>" `
  --dry-run
```

确认原视频、完整运行资源、原记录 SHA 与阶段一致后，再去掉 `--dry-run`。恢复输出模式由本次命令明确决定：默认纯文本；需要配图时增加 `--with-frames`，不自动继承旧记录的配图模式。始终使用新空目录，旧记录和旧图片不改写或删除，恢复回执保留原模式与本次模式。即使纯文本，浏览器仍严格核验每一原生帧与每个原生裁剪像素；不重做检测或移动识字，不重复已完成的代表精读。待办代表精读的校准复用该原裁剪中已经实际识别的移动读数，并明确记录为缓存校准、零新增移动模型调用；随后只补合法精读和由其派生的扩框待办。需要配图时重新从原片取得每张对应画面，来源不符即停止。恢复适配器单独记录 SHA，不冒充原运行资源。若资格校验失败，保留旧记录，解释状态，不强制继续。

## 固定区域旧入口：必须先核对画面

用插件的“视频字幕 · 测试版”页，或者宿主已有的本地视频预览，检查几处不同时间点的字幕位置。框选应紧贴一行文字，避开昵称、贴纸和包装字。

四个坐标依次为：左、上、右、下，占视频宽/高的比例（0—1）。例如插件显示顶部 76%、底部 80%，对应 0.76、0.80；这只是坐标换算，不是所有视频通用位置。

没有可核对的画面时，请用户确认区域或在插件中预览，不盲目启动整条识别。

## 固定区域旧命令（兼容）

依赖原 Skill 的 Python + Playwright + 本机 Chrome。模型和浏览器端识别代码已随 Skill 放在 `assets/subtitles/`。全部识别资源从本地提供，浏览器请求被限制到本次本地输入和随包资源。

```powershell
python scripts/extract_video_subtitles.py `
  --video-file "<已下载的视频.mp4>" `
  --out "<新的字幕输出目录>" `
  --region "<已核对的左,上,右,下>" `
  --dry-run
```

先核对 Dry Run，再去掉 `--dry-run`。若能从下载记录确认作品 ID，可以增加 `--work-id "<作品ID>"`；不得根据本地文件名猜作品 ID。

旧模式的产物（不包含新逐句配图）：

- `视频字幕.txt`：UTF-8，按采样观察顺序，每段带 `[分:秒.百分秒–分:秒.百分秒]` 观察范围、来源与局限说明。缺失时间显示“时间待确认”，不延伸至下一句。适用于素材回看、脚本整理和剪辑定位，不是精确 SRT 轴或完整音频转写。
- `字幕识别记录.json`：输入视频 SHA-256、作品 ID（如已确认）、区域、采样间隔、已处理帧数、不确定帧数、原始观察、每段观察时间与状态；`runtime` 记录实际引擎名称、版本依据、模型／字典／代码哈希。该身份记录不是准确率证明。

旧区域模式不覆盖已有结果；更换区域或重试时另建字幕目录。每轮进度落盘，中断保留已有文字；旧区域命令不支持跨进程暂停续跑。插件字幕页面支持当前会话暂停、继续、取消及导出部分文字，关闭页面结束任务。

## 插件与 Skill 路径区别

已有插件脚本工作包优先按 [脚本工作包接力](script-work-package.md) 读取。插件的图文浏览 HTML、可编辑 Excel 和品牌工作列不等于本命令行的 CSV／图文导出；本命令行未新增插件式脚本 Excel 生成器。

插件可具有当前原生播放器逐帧读取与自动推荐区域等独立路径，其适用页面和验收状态以对应插件版本为准。本 Skill 的稳定修复首包仍只读取作品记录确认的本地文件；无需用户把下载文件上传云端。

本交付包的新自动模式与 v0.11.201 插件共用字节一致的检测、精读、简体、字幕区域、工作稿、配图和调度模块。固定身份标签与连续语言字幕分开；字幕换位置、短暂移位和检测很密的局部画面，必须依据本视频的原生来源、独立前后字幕、实际字形与时段排他性提出补读，不能靠标题或参考答案推测。逐字补齐与末帧裁框残句可按严格源证据归为一个工作卡，全部原始读数及关键分歧保留，不视为已确认语义正确。

旧区域模式仍保留旧资源。命令行只接本地原片，不具备插件的当前网页逐帧读取、播放器暂停/还原、页面切换隔离、OPFS 接力或本机历史管理。源码、实际执行、文字质量、插件当前实页、商店和 GitHub 发布状态分别报告；本包未自动替换已安装 Skill，也不是所有测试视频已达到百分之百正确的声明。

## 可选：接入单作品 all 任务

单作品下载后可以直接接力，无需用户再次选择文件。自动模式增加：

```powershell
python scripts/run_foundation.py all `
  --video "<明确单作品链接>" `
  --subtitles --subtitle-detected-lines `
  --profile-dir "<原私有登录目录>" `
  --out "<新的交付目录>" `
  --skip-comments --zip --dry-run
```

此命令默认仅输出字幕。需要逐句配图时再增加 `--subtitle-with-frames`，它同时要求 `--subtitles` 与 `--subtitle-detected-lines`。需要旧区域模式时将 `--subtitle-detected-lines` 换成 `--subtitle-region "<已核对区域>"`；二者不能并用，旧模式不接受配图开关。`--subtitles` 不接受主页、搜索、选择文件、多个作品、非 primary 素材或 `--resume`。无需字幕时不加字幕参数，原下载流程不变。商品资料与评价仍需各自原有明确开关，不随字幕自动采集。

作品下载完成后，严格以该作品记录中的本地视频文件为输入，在其素材文件夹下新增 `字幕/`，无需再让用户选择或上传视频。识别失败时保留作品、商品与评论文件，整体退出码变为 3；不会把字幕失败改写为素材下载失败。普通说明与 `foundation_manifest.json` 分别记录字幕状态，成功接力的汇总同时携带实际引擎与模型哈希。
