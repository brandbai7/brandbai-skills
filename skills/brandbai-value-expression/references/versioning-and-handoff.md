# 版本与下游交接

## 上游变化

初始化时记录商品价值底座版本、更新时间、P0状态和必需文件哈希。出现以下任一变化时，本版卖点呈现标为`stale`：

- 商品、SKU或标准成交单元变化；
- 商品事实、表达边界或上游文件哈希变化；
- P0重开、替换、停止或推荐价值改变；
- 原P0/P1/P2的下游准备度变为blocked；
- 新页面或包装与当前识别锚、事实或现有表达冲突。

更新时只重新扫描受影响价值、槽位、VIS和验证任务；不为排版重编号，不删除旧版本。未变化资产保留稳定ID。

同一商品价值底座首次卖点呈现使用 `V1`。保留旧交付并形成修订版时显式递增 `output_version`，例如 `V1 → V2`；初始化器据此生成新的 `value_expression_id`。修订版不得与仍保留的旧版复用同一个 `output_version`。

## 页面和用户资料增量

新增页面表达若只是对既有事实的传播语言或可见形式，在本轮登记为 `PEX-` 并回指上游事实；不要求为了盘点页面画面反复重做商品价值底座。若包含新事实、精确证据字段、跨SKU信息或冲突，先回到商品价值Skill更新事实和价值，不在本Skill静默吸收。

新增用户语言只能增强场景、动作、感觉词、结果词、比较词和自然比喻，不能覆盖商品事实或把单例体验扩成普遍功效。

## 交给内容组装

下游读取：

```text
expression_manifest.json
upstream_snapshot.json
existing_expression_ledger.jsonl
vis_ledger.jsonl
validation_ledger.jsonl
gap_ledger.jsonl
```

下游必须同时确认业务目标、目标动作、主作业对象、目标人群、触发时刻、账号或达人语法、执行资源、当前SKU、入口和交易承接。任一关键输入缺失时只能预选VIS，不得排列确定信息链或生成正式脚本。

具体达人任务还必须读取当前有效达人账号分析和真实试用/共创资料；缺少时不得生成第一人称体验、达人推荐原话或最终达人方向。

## 交给资产回写

建议VIS默认是`suggested_untested`，页面已有是`page_existing_unvalidated`。只有具备真实内容/直播/页面版本、对应内容ID、样本量、数据指标、观察窗口与必要对照，才能进入卖点呈现资产回写并升级为`candidate`或`validated`。

回写必须说明：必须保留、可变、待补强、不建议误用和下一轮应用；不能用一个爆款证明全部卖点，也不能把页面采用归因成转化效果。
