# 交付合同

## 目录

1. 普通版文件

## 1. 普通版文件

```text
01_卖点可视化呈现.md
02_资料说明与验证计划.md
```

`01`面向客户、品牌执行同学和学员，最多展示5个核心呈现资产和3个建议验证任务；`02`保留页面表达盘点、逐价值六路扫描、十二槽位完整性、资料缺口和失效规则。完整VIS与索引保留在`data/`。

普通版隐藏内部ID、Schema、脚本、运行过程、本地绝对路径和客户隐私，但保留上游版本、商品/SKU、事实/假设/已验证/待补边界。

## 2. 状态定义

### analysis_status

- `complete`：对当前有效上游的可沟通价值完成六路、十二槽位、VIS与验证计划；不等于呈现有效。
- `partial`：已形成可用资产，但页面素材、用户语言、业务或执行输入存在重要缺口。
- `insufficient`：无法形成可靠感知资产，只输出资料和缺口。
- `stale`：商品、SKU、上游事实或P0变化，当前输出停止调用。
- `draft`：工作中，不得正式交付。

### delivery_status

- `ready`：结构和上游一致，可供下游正式读取；仍保留各VIS验证状态。
- `conditional`：可阅读和有限调用，必须继承缺口与限制。
- `blocked`：不得进入正式下游任务。
- `stale`：旧版停止使用。

## 3. 文档结构

`01_卖点可视化呈现.md`固定包含：卖点感知化总览、品牌语言翻译为用户语言、核心卖点感知化呈现卡、内容功能位置、五大作业对象调用地图、第一轮内容验证、资产回写闭环、当前边界与下一步。

每张呈现卡至少包含：对应商品价值、用户感知任务、主/辅助路径、画面、动作、声音、字幕、道具、场景、特效/BGM、商品承接、必须保留、可变部分、不建议误用、适用对象、验证状态和边界。

`02_资料说明与验证计划.md`固定包含：商品和上游版本、页面已有呈现、六路扫描、十二槽位扫描、当前能做/不能做、缺口和版本失效规则。

内容功能位置和五大作业对象地图只说明“哪里可以调用”，不生成固定顺序、完整内容方向、脚本或Brief。

## 4. 正式交付门槛

- 上游商品价值状态可调用，商品、SKU、P0决策和版本明确；
- 上游快照、文件哈希和当前输出版本完整；
- 每个可沟通P0/P1/P2恰好扫描六条路径，并选择1主+1—2辅；
- 01—12十二槽位全部判断，适用关联VIS，不适用写明理由；
- 每个可沟通价值至少有一个VIS；
- 普通版核心卡先覆盖全部可调用P0/P1；P2仅在解除真实购买阻力或已有品牌战略/用户证据时进入，允许少于5张，且不使用一级识别锚占核心名额；
- 每个VIS只有一个主价值、一个主要决策任务，并回指有效事实；
- 每个VIS五条基础轨完整，扩展轨逐项判断；
- 使用周期、频次、减少补货、一次买够或够用一阵由上游事实直接支持，不由包数、容量、重量或件数自行换算；
- 上游声明冲突的到手件数、套组清单或装箱内容不得进入路径、槽位、VIS、验证任务与普通版；
- 安全性证据、固定字幕、验证任务与指标必须语义同题，不得用安全检测抵消孕哺禁忌或替代稳定性/失活证据；
- 外部品类、竞品、普通款或传统方案的同框/对照/对比有上游直接比较证据；自身身份或资质事实不替代外部比较证据；
- single_variable 只有一个已锁定具体变量，不含二选一素材或多维联动；全部版本保留症状分层、说明书/医务人员指导、禁忌、注意事项、警示和适用边界；
- 页面已有表达与新增建议分开；提供补充商品素材时，页面盘点已进入 `PEX-` 结构化账本，普通版与data保持同步；
- 页面截图、原件、检测小字和认证名称的证据等级没有被升级；
- 单包内容物证明保留未拆封单包、连续展示与不补料／不换包条件；
- 验证任务的对照版、测试版、唯一变量、指标获取方式和判断规则一致；证据画面测试不同时改字幕，单包证明不使用预摆盘对照，没有统计设计不写显著性；验证状态没有升级造假；
- 普通版最多5张核心卡、3个验证任务；
- 普通版无内部ID、绝对路径和模板占位符；
- 上游变化、资料缺口与停止边界明确。

使用`validate_value_expression_delivery.py`校验；退出码为0才可交付。
