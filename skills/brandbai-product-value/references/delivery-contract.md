# 交付合同

## 目录

1. 普通版文件
2. 状态定义
3. 两份文档结构
4. 正式交付门槛

## 1. 普通版文件

正式普通版只有：

```text
01_商品价值底座.md
02_资料说明与缺口.md
```

不要把内部代码、脚本说明、私有方法模块编号、本地绝对路径或实现过程写进普通版。正式交付根目录也不得包含事后修正脚本或可执行文件。保留商品、SKU、事实来源类型、价值状态、资料边界和未知。

## 2. 状态定义

### analysis_status

- `complete`：本次输入的商品价值建模完成；不等于 P0 已被市场验证。
- `partial`：形成可用底座，但存在影响部分结论或下游使用的重要缺口。
- `insufficient`：无法确认商品/SKU或无法形成可靠价值。
- `stale`：上游资料变化使当前版本失效。
- `draft`：工作中，不得正式交付。

### delivery_status

- `ready`：结构一致，可供下游正式读取；价值仍保留原证据状态。
- `conditional`：可阅读和有限调用，但下游必须继承缺口与限制。
- `blocked`：不得进入下游正式任务。
- `stale`：旧版停止使用，等待重新编译。

## 3. 两份文档结构

`01_商品价值底座.md` 固定包含：一页结论、商品身份与识别锚、用户问题与购买决策、FABE 价值证据链、P0/P1/P2 分层、为什么选择当前核心价值、条件式下游应用地图、当前状态与下一步。

`02_资料说明与缺口.md` 固定包含：商品和 SKU、输入形态与成熟度、已读取来源、已确认事实/冲突/待复核、资料缺口及影响、当前能做和不能做、增量资料和版本说明。

普通版正文必须隐藏 `PV-/SF-/OBS-/CLM-/SRC-/F-/FABE-/V-/ANCHOR-` 等内部资产 ID、英文状态和技术字段名，但每条重要价值必须能回到结构化底稿。P0 假设使用“优先验证的核心价值”，不得写成“消费者已经认可”。P1 和 P2 各不超过 3 个；暂缓或禁止调用的价值不进入正式价值清单，但属于 P0 候选时必须进入候选比较并显示未入选原因；完整资产仍保留在数据底稿。“不能证明”的对象必须放在明确的“当前资料不能证明”标题下，不能单独列成貌似正向结论。

隐藏内部 ID 后不得留下 `(,)`、`(/)`、`(:…)` 等异常标点。SKU 确认状态和依据必须在两份普通版中显示。缺口优先级使用 P0—P3，并在“优先补充资料”中正确显示开放的 P0/P1 项。

如果 `analysis_status=insufficient`，`01` 只保留已确认身份和事实，不得为了完整而生成价值；`02` 成为主要交付。

## 4. 正式交付门槛

正式交付前必须满足：

- `product_manifest.json` 不为 `draft`；
- 商品、SKU、版本和完成状态明确；
- 所有来源、事实、识别锚和价值 ID 唯一；
- 本地来源先进入真实文件清单；每张图片生成同时绑定文件编号、原始相对路径、文件指纹和原图像素的审计卡，并通过时间随序号真实递进的正序初检和逆序复核；核验时间来自实际打开当下，晚于 `created_at`，时区偏移对应真实本地时钟，不能重复、固定间隔生成、晚于账本写入或落在未来；含文字来源先完成全部第三遍原文摘录，再开始第四遍复核；来源账本绑定对应核对记录，标题完全一致；
- 营养表、SKU、配料、储存、警示、FAQ、食用方式和对比信息按原文逐条登记；含禁止食用、请勿食用、不宜食用或遵医嘱语义的内容必须作为关键警示；关键主张进入事实，事实数字、口感词、使用限制与高风险词能回到所引原文；
- 每个事实能回到有效来源，或明确标为分析推导；
- 页面图片不在观察、来源、事实边界、FABE、价值、缺口或普通版中自证报告编号、日期、批次、证书编号和检测方法等精确小字；只有报告原件/PDF或官方验证页可将精确字段标为已核验；
- 每个价值至少引用一个事实或推导；
- 每个非暂缓价值及每个 P0 候选至少保留一条完整 FABE，并引用有效且与该价值直接相关的事实；FABE 的产品比较和交易叠加必须有直接来源，不得虚构另一类产品作为比较对象；用户旧习惯参照必须引用 `U` 证据，用户利益不得写成绝对化的“不用担心”；
- 互斥包数、总净含量/单包克重/包数算术冲突和疑似 OCR 残片必须停在资料缺口，不能因多遍记录一致而进入识别锚、FABE、价值或 P0；普通版表格不得保留以逗号、分号、冒号结尾的残句，以及“仅在 出现”“与等”等缺失对象的句子；
- 标题规格冲突时使用可确认的标准成交单元；动态活动补全年份时披露采集时间依据，并保留原文时刻和时区；不得增加原文没有的食用限制；
- `p0_candidate=true` 的价值与决策文件中的候选池完全一致；P0 推荐值存在时属于候选池且 `layer=P0`；普通版展示全部候选及未入选原因；
- P0 不以页面出现次数、覆盖页数、篇幅或可拍性判胜；无用户资料时不写很多或多数用户的集合性判断；
- 最多只有一个当前推荐 P0；
- `complete` 或 `partial` 至少有一个可用价值；
- `insufficient` 至少有一个资料缺口；
- 普通版没有模板占位符；
- `updated_at` 晚于本次全部核验事件，最终账本和报告生成后刷新 manifest；manifest 之后超过五分钟仍修改正式账本或报告视为未完成收口；
- 下游调用状态与分析状态一致；
- 价值范围不超过支撑事实覆盖的 SKU；普通版没有内部 ID、英文状态残留或表格多余符号。

公开商品页中与当前商品和 SKU 明确对应的内容可以作为正式交付依据；第三方证据缺失只影响证据等级和高风险表达边界，不自动把对应商品价值判为 `blocked`。

使用 `validate_product_value_delivery.py` 校验；退出码为 `0` 才能交付。
