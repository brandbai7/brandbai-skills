## 1. 判断对象

商品价值底座不是详情页摘要，也不是真实性审计报告。它要回答：这是什么商品和当前 SKU；信息来自哪里；事实可能帮助用户完成什么任务；哪个核心价值最值得优先验证；哪些价值只负责支撑选择或解除顾虑；当前能证明什么、不能证明什么；下游可以调用哪些价值。

SKU 优先以选择器、包装、规格表和商品信息区确认。标题中的“独立装”“礼盒装”等词组若与净含量、小包数量或当前选择项不能唯一对应，只能作为线索；用“标准成交单元 + 待确认名称”记录，不把标题片段直接当成确定 SKU。

本地资料先按真实文件名和内容指纹建立来源清单，再逐个打开准确文件并立即写核对记录。文件名是来源身份，不得按阅读顺序把“图文详情13.jpg”改写成“第8张”；也不得沿用旧交付对第几页是什么的判断。来源台账必须同时绑定原文件和逐文件核对记录，同一页面事实必须能回到清单中的精确相对路径。

两遍页面身份核对只能证明“打开的是哪一张图”，不能证明文字已经读对。完成两遍核对后，再重新打开含文字页面建立逐字原文主张并复核。营养表、规格表、FAQ、储存、禁忌、对比和检测页面优先按字段或问答逐条抄录，不能用概括性摘要替代；事实数字、适用/不适用人群和功效倾向词必须回到这些原文主张。

## 2. 事实到用户价值

先穷举事实，再完成：

```text
Feature 商品事实
→ Advantage 对真实替代方案的可能优势
→ Benefit 对用户任务的意义
→ Evidence 用户能够理解或核对的依据
→ V 商品用户价值
```

参数、成分、材质、工艺、认证和包装都不是天然用户价值。只有连接到明确用户任务，并保留事实和推导边界后，才能形成 `V-`。

合理推导必须写成 `H` 或待验证，不得扩大原始资料中的功效、比较结论或适用范围。没有竞品资料时可以形成内生价值判断，但相对优势只能标为待比较。

对食品和健康相关商品，用户任务写真实动作和顾虑，如“想把黄精加入日常饮食，但担心处理麻烦和口感”，不要先写“获得滋养收益”。检测报告只能按报告对象和页面展示范围支撑主张，不自动变成“安全认证”“安全底线”或“确保品质”；零脂肪、无硫熏和单一配料也不能自动推出特定健康或敏感人群适用性，单一配料也不自动等于无添加或无防腐剂。页面图片中的报告编号、日期、批次、证书编号和检测方法等小字字段直接省略；只有报告原件/PDF可定位文本或官方验证页才能核验。页面只写“反复蒸晒”时不得改成“九蒸九晒”；页面只写“入口温和”或“去麻”时不得改成“无刺激”。

## 3. FABE 完整推导

每个准备进入 P0、P1、P2 的价值必须先写一条可独立阅读的 FABE：

| 层 | 必须回答 |
|---|---|
| Feature | 当前商品或当前 SKU 到底有什么事实，不写空泛形容词 |
| Advantage | 相对用户旧习惯、普通方案、真实替代或具体问题，带来什么不同；没有竞品资料时只做内生优势，不伪造领先 |
| Benefit | 用户因此少做什么、少担心什么、得到什么或更容易完成什么任务 |
| Evidence | 用户能从页面、包装、演示、参数、检测或可见结果中核对什么 |

同时保留参照系、用户语言、推导状态与边界。FABE 不是给四个格子重复写同一句话：Feature 不能直接跳成 Benefit，Evidence 不能自动成为核心价值，Advantage 缺少外部比较时要写清参照只来自用户问题或旧习惯。Evidence 必须直接支撑当前 Feature→Advantage→Benefit 链；不能因为另一张检测页“看起来更权威”，就把它挂到与该检测无关的口感、便利或场景价值上。

普通版必须让客户和学员看到这条事实到利益的推导链，但隐藏内部资产 ID；完整字段保留在 `fabe_ledger.jsonl`。

## 4. 六层分离

| 层级 | 回答的问题 | 记录方式 |
|---|---|---|
| 商品身份 | 这是什么、哪个品牌、哪个 SKU | `ID-` |
| 识别锚 | 用户下次如何认出它 | `ANCHOR-` |
| P0 | 为什么值得优先记住和选择 | `V-`，layer=`P0` |
| P1 | 如何帮助理解、适配和完成选择 | `V-`，layer=`P1` |
| P2 | 凭什么相信、如何降低顾虑 | `V-`，layer=`P2` |
| 动态交易 | 当前怎么买、买什么、到手什么 | `DYN-` |

身份不等于价值；识别锚不等于 P0；证据不等于价值本身；价格和赠品不等于长期价值。

## 5. P0 候选与决策

每次至少检查品牌战略指定方向、成分材质机制和工艺可能带来的体验、用户希望减少或获得的结果、结构和使用方式解决的问题、规格性能是否形成可持续选择理由，以及有商品事实支撑的情绪或品牌意义。

先把候选分成战略差异候选、类目门槛、购买支撑、信任信息、识别锚和动态交易，再比较战略候选。品牌指定方向必须进入候选，但不自动获胜。

分别评估：

- 战略价值潜力：用户问题重要性、竞争差异、选择影响、品牌占领性、跨触点延展和非促销持续性；
- 当前执行成熟度：事实清晰度、证据充分度、用户可理解程度、发布可用性、用户/经营信号和下游准备度。

两轴只使用高、中、低和依据，不机械合并总分。执行成熟度高不自动等于战略价值高；当前难表达也不自动否定战略潜力。

推荐 P0 必须写成一个不可拆的核心用户价值，并绑定商品、SKU、用户状态、场景和参照。没有足够战略或竞争输入时，状态只能是 `P0-HYPOTHESIS`。

## 6. 证据与表达边界

每个 `V-` 都要保留支撑的事实或证据 ID、来源类型、适用 SKU/人群/场景/时间、当前不能证明什么，以及下游是否 `ready`、`conditional` 或 `blocked`。

价值范围默认是当前 SKU。只有支撑该价值的每条事实都明确写明覆盖全部 SKU，才允许把价值范围扩为全 SKU；当前 SKU 尚未完全确认时只能收窄，不能放大。

品牌或商家公开发布、且能明确对应当前商品和 SKU 的详情页、包装、说明书、官方 FAQ 与品牌手卡，本身就是商品价值分析可使用的公开证据。可以据此建立商品事实、价值和当前公开卖点，不要求每条结论都先取得第三方证明，也不要因缺少检测原件就自动把公开商品主张标成禁止使用。

第三方报告、认证、研究和批次材料用于提高证据强度、支持更高风险或更具体的主张，以及处理冲突；它们不是所有商品价值的准入门槛。只有以下情况才降级或暂缓：来源与当前 SKU 无法对应、多个公开来源互相冲突、资料已过期、表达明显超出公开页面范围、涉及疾病治疗或缺少必要依据的绝对化承诺。

普通版可以直接写当前有效的商品价值，不必在每句话前重复“页面宣称”。证据等级、来源类型和限制放入证据链与资料说明中即可。

评论和问答只能说明用户语言、体验线索、顾虑和分化。单例体验不能证明普遍功效，频次不能自动决定 P0，自报购买不能证明成交归因。

## 7. 禁止越界

商品价值阶段不能输出 VIS 或完整卖点呈现，不能编排画面动作、选题钩子、信息顺序、脚本、达人人设适配、第一人称体验或合作结论，也不能生成超出商品资料、证据和授权范围的功效、比较或绝对承诺。

本阶段只向下游交付稳定事实、价值、P0 决策和感知目标。具体“怎么让用户感受到”由 `brandbai-value-expression` 完成。
