# 版本与下游交接

## 增量资料

收到新详情页、手卡、证据、用户反馈、SKU、价格权益或经营数据时，不从头建立平行底座。先记录新增、修改、冲突和失效字段，受影响的来源/事实/价值/P0 决策，商品和 SKU 是否变化，是否触发 `P0-REOPEN`，以及哪些旧输出变为 `stale`。

保留旧 ID 和版本映射。无变化资产不重写，动态价格和权益按时间追加，不用新值覆盖旧快照。输出本次改变了什么、没有改变什么、下一步还缺什么。

## P0 重开

以下情况评估 `P0-REOPEN`：

- 新品牌战略挑战旧方向；
- 新品升级点、SKU或成交单元改变；
- 用户、竞品或类目证据改变差异判断；
- 真实使用反馈与原假设冲突；
- 原 P0 实际只是识别锚、交易权益或表现形式；
- 证据原件或合规边界发生重要变化。

重开后冻结旧 P0 的新下游使用，保留历史记录，重新评估候选并生成新决策。旧的卖点呈现、匹配、Brief 和执行物标记 `stale`。

## 交给卖点呈现 Skill

至少提供：

```text
product_manifest.json
fact_ledger.jsonl
anchor_ledger.jsonl
value_ledger.jsonl
p0_decision.json
gap_ledger.jsonl
```

`brandbai-value-expression` 只能为当前有效的 P0/P1/P2 设计感知方式，回指现有事实、价值、识别锚和 P0 决策，并继承“不能证明什么”和表达边界。它不能重选 P0、修改事实、把缺口补成结论或把呈现便利性写成战略价值。

## 交给商品匹配 Skill

商品匹配必须同时读取当前有效商品价值底座、当前有效账号或影响力对象分析包，以及双方的缺口、失效状态和证据边界；如已完成，再读取卖点呈现资产。

任一上游为 `blocked` 或 `stale` 时停止正式匹配。商品匹配不得为了形成合作方案而改写账号事实或商品价值。
