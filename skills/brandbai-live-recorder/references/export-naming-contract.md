# 导出命名与关联 · 0.22.6

只改变新导出的可读名称，不迁移、重命名或覆盖旧文件，不改变浏览器默认下载位置。下载和分析保持独立。

## 浏览器 ZIP 与独立商品文件夹

| 内容 | 可读名称 |
| --- | --- |
| 商品目录 | 抖音_名称_商品目录_日期_时间.zip |
| 商品资料 | 抖音_名称_商品标题_商品资料_日期_时间.zip |
| 商品评价 | 抖音_名称_商品标题_商品评价_日期_时间.zip |
| 直播记录 | 抖音_直播间名称_直播记录_日期_时间.zip |

- 只使用该次资料已观察的名称；缺名称时独立商品包使用“直播间”，缺商品标题直接省略。不写“店铺待核”“商品待核”“待核 ID”、房间编码或批次码。不从下载目录、搜索词或后来切换的页面猜名称。
- 独立商品包名称和标题各最多 32 字符，只截取原文，不编写营销简称。完整原文在 JSON 保留。
- 时间显示 `2026-09-17_15-11-09`；JSON 保留带时区的原观察时间及实际导出时间，不把导出时间冒充观察时间。
- 文件夹与其旁侧 ZIP 同名，只追加 `.zip`。不同请求同名时按 ` (2)` 等顺序另存；目录创建与 ZIP 创建拒绝覆盖。同一请求仍不能在助手重启后无提示地重复创建。
- 名称经过非法路径字符、控制字符及 Windows 保留名处理。价格、评价数、完整性不进入名称。
- 直播 ZIP 沿用已发布的冻结场次命名规则，见 [直播记录资料包合同](recording-bundle-contract.md)。不修改运行中媒体路径、场次标识与录制调度。

## 包内文件和身份

`00_资料说明.md` 为阅读入口。保持商品资料、商品身份、目录、评价、下载清单及完整性等既有机器文件名称与字段，避免破坏后续提示词和关联流程。

`导出信息.json` 继续使用 `brandbai.export.v1`，保留 `export_id`、`material_type`、实际 `package_name`、`observed_at`、`exported_at`、`product_identity`、完整标题／店铺及来源房间。内部批次及观察引用不是平台商品 ID，未知真实 ID 保持空值，不伪造。

商品图片仍按 `主图/`、`详情图/`、`规格图/` 分类，目录缩略图在 `图片/`。新图片使用 `主图001.jpg`、`详情006.webp` 等简洁名称，不加未知 ID。数字是采集次序，不声称等于页面轮播位置；仅有真实位置证据时使用 `轮播002_主图.jpg` 或 `轮播001_视频.mp4`。来源、SHA256、保存状态及 SKU 到文件的映射继续保留。视频封面不能冒充视频，未收齐不能标完整。

## 关联边界

文件名只供人阅读，不作为关联键。详情与评价通过同一个 `product_identity` 关联：有公开证据的真实商品 ID 优先；未知 ID 时，只允许已绑定同一打开面板的 `product_ref`。不同店铺 ID 不合并，不跨页面或日期凭标题相同猜配。SKU ID、目录编号和房间 ID 不能冒充商品 ID。

目录编号仅属于对应房间和观察时点；后补目录不覆盖旧版本，也不能倒推早先话术。录制的私有工作目录、媒体和台账保留现有内部路径规则，不改写历史场次。
