# 运行与交付合同

本文件描述当前可用行为，不按历史发布顺序叠加规则。入口与版本见 [SKILL.md](../SKILL.md)；商品、评价、互动、身份和交付分别遵守对应专项合同。

## 运行路线与依赖

- 无浏览器：Python 3.10+、本地 FFmpeg／FFprobe、固定 `streamget==4.0.10`。支持一次探测、单房录制、多个不同房间并行录制及公开房间指标，不含网页评论或当前商品卡。
- Chrome：最低 114，配套扩展与 Windows 本机助手。单个活动录制，可选页面增强；目录、单商品资料、买家评价可独立下载。安装 Skill 不自动完成插件加载或助手安装。
- 命令行与本机服务不要求可视浏览器来录制媒体；页面功能不能用无浏览器脚本替代。
- 不提供循环等开播、无人值守下一场、无限重连、其他平台录屏、无浏览器实时评论、商品视频下载、原生 XLSX 或自动经营分析。

## 本地检查与输入

`doctor` 只检查本地依赖，不访问直播间或安装环境；`dry-run` 只校验参数，不录制、不创建交付目录。`probe` 联网解析一次公开房间，不创建交付目录或输出拉流地址。

普通录制使用 [录制输入合同](input-contract.md)：链接为唯一必填项，默认标清、30 分钟、不分段；总时长 1—1440 分钟，不分段最多 360 分钟。分段默认 10 分钟，可选 1—360 分钟或 60—21600 秒，不能超过总时长。高清／原画不可用时允许降级并记录实际值。

简化入口将明确录制请求视为操作指令；底层 `start` 与独立 API 保留显式授权参数。只保存使用者有权处理的公开内容，不扩大为商用／传播授权。没有活动任务时不主动开始录制或页面采集。

多房入口要求至少两个不同规范房间，默认最大并发 3、硬上限 5；每个独立场次、独立状态。Chrome 全局只控制一个活动录制，切换页面不创建第二个录制，也不混入新房间事件。

## 页面来源与授权

- 核心 CLI 接受 `https://live.douyin.com/<数字房间ID>`；不要把任意搜索 URL 直接传给录制脚本。
- Chrome 可识别相同规范直播页，或准确 HTTPS `www.douyin.com`／`douyin.com` 的 `/search/<词>`、`/jingxuan/search/<词>` 中明确打开的直播；搜索入口必须有唯一有效 `live_web_rid`，且唯一 `type` 为 `live` 或 `general`。普通搜索结果页不视为直播间。只保留规范房间，不保存搜索词、跟踪参数。
- 缺当前页读取权限与“不是直播”分开。用户主动点击才申请可选抖音站点权限；可拒绝并使用工具栏 `activeTab` 临时授权。站点授权不表示可以处理普通搜索或自动采集。
- 切页、权限变化、侧栏重开重新核对，丢弃旧结果。不自动导航、刷新、切换或聚焦用户页面。
- 双采样核对商品／评价的标签、文档、房间、唯一面板与身份，不能用标题相似替代。无可用浏览器操作能力时由使用者操作配套插件。

## 私有运行环境

- StreamGet 依赖不打入 Skill ZIP 或客户资料包。依次发现当前 Python 环境、显式覆盖、工作区祖先的私有 runtime、用户私有 runtime。
- `doctor` 不联网；有效的探测／录制请求才允许首次准备依赖。按宿主权限审批联网和私有目录写入，不绕过限制、不索要普通用户提供依赖路径。
- 自动准备最多一次，失败返回 `runtime_dependency_unavailable`。公开状态只含来源类型、版本和是否本次准备，不暴露 pip 原始日志、代理值、令牌或私有路径。
- 拉流地址只驻留进程内存，不写入 Skill、日志、台账或输出。不得提取、复用浏览器凭据或绕过平台访问控制。
- 解析失败分为网络不可用、空响应、结构变化、访问校验等稳定原因；不把网络错误写成直播间失效。

## 录制、媒体验证与断流

1. 规范房间，冻结独立场次与目标时长，检查可用磁盘空间（默认至少 10 GB）。
2. 正常公开解析开播状态；未开播返回 `not_live` 并结束，不后台等待。
3. FFmpeg 复制码流写入 TS；分段时仅设置严格早于总时长终点的边界，非整除尾段保留。
4. 已得 TS 复制码流转封装 MP4，再用 FFprobe 核验视频、音频、容器、分辨率和时长；可选 `--full-read-check` 整文件读取与 `--sha256`。默认保留原 TS，转封装失败更不能删原片。
5. 媒体启动 45 秒无推进或录制中 30 秒无推进会结束本次输入，不能无限挂起。暂时故障且未产生媒体时有一次受限启动重试。
6. 有限时任务中，短暂断流最多重新解析同一公开房间两次，在原截止时间内继续；原媒体、各次尝试和未观察区间保留。不补回缺口，不换房，不无限延长。无时限高级任务不做中途自动重连。
7. 到用户设定时长、手动停止、服务结束或源异常分别留原因；输出只覆盖真实观察窗口，不能把正常进程退出当作平台下播。
8. 控制连接暂时不可达不等于 FFmpeg 已停止；查询原任务，不新建重复录制、不强制重启助手。

只导出任务相对路径。媒体 `valid_video_only` 不可称声画完整；`short_fragment` 可保留但不可称足额片段；`invalid_media` 不能算成功视频。

| 结果 | 含义 |
| --- | --- |
| `complete_observed_session` | 已确认直播结束，实际观察窗口内媒体有效且无更高优先级失败；不等于全天完整 |
| `partial_time_limit` | 已到设定录制时长，不是下播证据 |
| `partial_manual_stop`／`partial_service_stop` | 用户或服务结束本次观察 |
| `partial_disconnect` | 媒体／源结束但未确认下播，保留已有媒体与缺口 |
| `partial_conversion` | 至少一段 MP4 转封装失败，保留可用原片 |
| `partial_service_restart` | 本机服务重启后的未完成任务，不能伪装仍在录制 |
| `failed_no_media`／`failed_storage` | 无有效媒体或磁盘安全检查失败 |
| `not_live` | 单次检查未开播，不外推此前或此后 |

## 房间指标与可选页面互动

无浏览器录制默认每 15 秒采样公开房间指标，允许 10—300 秒；`--no-collect-room-metrics` 可关闭。在线人数、点赞累计、购物车数量、带货标记只在来源可用时记录，未知不填 0。在线人数是同时在线快照，不是进房量、独立用户或留存率。

Chrome“同步记录直播信息”默认关闭。开启后按用户选择分别记录可见评论、弹窗商品卡和页面指标；未选项不通过其他事件间接读取。任务私有状态只保存原三个范围开关用于恢复，不据此自动开启下一次采集。

评论 DOM 变化监听兼容显示节点复用，但仍只记录页面首次可见时间。商品卡状态、目录“讲解中”标记、实际主播口播与场控点击不是同一种证据。时间未经延迟校准不能当作精确视频秒数。详见 [互动合同](live-interaction-contract.md)。

- 关闭侧栏不停止本机录制或原页面采集；重开恢复原任务。关闭／冻结／离开原页会导致互动缺口，即使媒体与在线人数仍继续。
- 暂时切到其他标签不主动停止媒体，但不保证原网页持续刷新评论。不要在其他设备或窗口以同账号进入同一直播间；账号被挤出时提示人工恢复，不自动抢占。
- 商品详情／评价面板覆盖弹窗时暂停该项观察并留空档；评论与指标继续尝试，但必须按实际事件核对，不能承诺都完整。
- 活动录制同房间出现明确节能暂停提示时，最多尝试两次精确“继续播放”并验证；不开评论也可启用该播放保护。不得点击客户端入口、泛化模拟活跃或抢焦点。
- 短时事件发送故障有最多 300 条待发送缓冲；超限留痕，不把旧任务缓存混入新任务。180 秒无新评论只作连续性风险提醒，不推断无人评论。
- 插件重新加载后旧脚本上下文失效必须停止轮询。只在同房间探测无接收者时按需注入包内固定脚本，重接同一任务原范围，不执行任意远程代码。

## 本机服务与启动

- 只绑定 `127.0.0.1`，助手按 8765、18765、28765 尝试可用端口。不关闭、抢占或冒充其他本机进程，不监听局域网／公网。
- 私有令牌、SQLite、设置与任务缓存和发布包／客户交付分离，不输出令牌。
- 服务健康检查公开无敏感信息；配对只接受匹配的扩展 Origin／ID。会话短时有效、绑定扩展，普通网页不可调用；业务接口均按鉴权和各自白名单校验，不接受任意路径、命令、原始 DOM、收货或支付字段。
- 同一活动房间重复创建幂等；停止幂等。不同房间 CLI 可并行，Chrome 创建第二个活动录制返回冲突。
- 助手离线才唤起启动页，最长等待 60 秒；未处理的原生确认不定时关闭。就绪或用户明确取消才关闭本次仍为启动页的标签并返回。
- 超时清除待执行请求；迟到连接不补交操作。返回后再核对原标签和房间，不能将启动期间切换的新页面当原对象。
- 助手在线但配对失败时显示连接原因，不重复唤起。并发连接合并，自动重试间隔不少于 30 秒，用户可明确重试。
- 更新／重启助手必须先确认录制、商品与评价下载均空闲，不强停；旧历史与保存设置不移动。

接口由 `scripts/local_service.py` 及专项合同定义。查看服务状态优先 `recorder_assistant.py status`；`run_local_service.py show-token` 是高级私有恢复入口，不是正常配对步骤，也不得把其输出放入对话。商品、评价、交付接口只能用于该明确任务，不作为任意页面接口代理。

## 文件交付与状态核对

Chrome 录制／目录／图片规格／评价：每次任务整理一个 ZIP，交浏览器默认下载位置。不要提供旧版首次选目录流程。只有 Chrome 确认下载完成且字节数一致才显示“文件已下载”；读取完成、文件整理完成和传输完成分开。重试已有包不重新采集；历史同名文件不覆盖。

无浏览器简化入口仍按 [输入合同](input-contract.md) 输出独立目录，可用 `--out` 指定输出根位置。浏览器路径规则不能套到 CLI。录制包结构由 [录制资料包](recording-bundle-contract.md) 定义，商品和评价保持独立包、共同 [商品身份](product-identity-contract.md)。新名称遵守 [命名合同](export-naming-contract.md)，不迁移或改写旧文件。

`data/` 中的任务、场次、分段、缺口、房间指标与可选页面事件供复核；某类没有记录时其文件可能不存在。录制 ZIP 中评论、弹窗商品、指标分别进入 05、06、07 分区，不将弹窗缩略图称作完整商品资料。

停止后短暂等待互动尾批；晚到数据只提示更新包，不覆盖已下载文件或偷偷重复下载。服务异常重启保留已写部分，不自动重新录制。关闭浏览器后未交付包可在下次打开时手动下载，不批量重放历史任务。

## 验证与故障处理

依次区分静态合同、单元测试、隔离合成页面、发布包核验、本次真实页面结果。任一较低层通过都不能写成真实全量采集通过；真实短测也不能代替数小时、弱网、下播与所有商品布局。

本地测试 `synthetic_smoke.py` 不访问真实直播；`--test-mode` 的短片段须带测试标识，不能混入业务证据。行为维护跑对应 Python／Node／隔离 Chromium 用例；仅文档同步不自动触发真实录制或页面下载。

用户问“为什么停了／是否完整”时先只读提供的 ZIP：核对实际媒体、条数、停止原因、采集空档和文件清单。用户要求修复才实施；不因有诊断材料就自动打开直播、购买商品、切页或重新采集。无法证实的字段写明未知，而不是用界面状态替代数据。
