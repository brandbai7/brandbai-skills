# 直播互动协同 0.12 合同

0.22.4 商品详情或评价面板占用时，评论与视频继续执行自己的采集链路；弹窗商品暂停观察并记录起止空档，不能把不可观察解释为无弹窗。未勾选商品卡记录时，不为此额外检查商品。页面指标在覆盖期将商品卡是否可见保留为 null。评论是否持续采到仍取决于页面是否更新，不能由视频持续或在线人数更新推断评论完整。

0.22.1 将总开关显示名更新为“同步记录直播信息”，原授权布尔开关不变。评论表不再混入弹窗商品与指标，两者在同一 ZIP 内独立分区；计数与时间含义仍遵循本合同，交付结构以 [直播记录资料包合同](recording-bundle-contract.md) 为准。

本合同约束评论、房间指标、场控商品卡、主播转写和录屏之间的时间对齐。采集架构以无浏览器本地录制为核心：StreamGet 可直接解析的公开房间指标由本地低频轮询获取；没有普通观众通用官方读取接口的评论与当前商品卡，只能使用使用者主动开启的当前页面可见信息增强。不访问平台后台、Cookie、用户真实 ID、订单、GMV 或成交归因。当前 Chrome 插件阶段只采集和落原始事件，不自动转写或分析。

## 业务目的

采集不是终点。交付用于回答：主播如何承接评论；商品弹窗出现或切换时，主播是否同步完成商品身份、价格／权益、卖点、异议和行动指令的承接；哪些问题在实际观察窗口内未看到回应。

## 无浏览器来源边界

- StreamGet 的标准房间解析可支持录屏、开播状态、标题、在线人数、点赞累计、带货标记和购物车数量，不提供实时评论流或当前讲解商品事件。
- 抖音开放平台的直播评论能力需要已准入、已申请权限并挂载在主播直播间的直播小玩法／互动工具，不是任意观众读取所有公开直播间的通用接口。
- 讲解卡动态更新是已授权应用更新指定直播间卡片的能力，不是观众侧查询当前商品弹窗的读取接口。
- 因此本版本不加入逆向签名、Cookie 提取、隐藏接口或风控绕过。任意公开直播间仍可无浏览器录屏并采房间指标；实时评论和精确商品弹窗只能等待合规直连来源，或作为用户主动打开页面时的可选可见增强。

## 时间含义

- `observed_at_epoch_ms` 是本地采集器第一次观察到事件的本机时间，不是评论的平台发送时间或服务器时间。
- `recording_offset_seconds` 由本机服务用任务开始时间换算，只表示相对录制任务开始的墙钟偏移。
- `streamget_room_poll` 与录制使用同一无浏览器房间来源，仍受请求往返和采样间隔影响；页面增强还会叠加浏览器播放缓存。未经延迟校准，墙钟偏移不能写成逐帧精确的主播响应时间。
- 周期快照事件的真实出现时间只落在“上一采样时间—本次首次观察时间”区间；首个快照中已经存在的评论没有可知下界。
- Chrome 内容脚本以 DOM 变化监听评论，并兼容评论列表复用同一显示位置后替换昵称／正文的情况；文字变化会短暂合并后重扫，活动任务探测同时提供低频安全复核。商品卡仍每秒检查一次；记录的是浏览器首次看见时间。它通常可达到秒级以内／约秒级观察，但仍不能获得平台服务器评论发送时间或场控点击时间，也不能保证捕获快于页面实际可见刷新速度的每一条内容。
- Doubao Lite 只提供机器文本。当前时间来自本地音频切块，默认每块 10 秒，可显式选 5—60 秒；保留原媒体偏移。不把尚未实现的语音活动分段当作现有能力，不采信模型自行生成的逐字时间戳。

## 页面采集开关

- “同步记录直播信息”默认关闭；关闭时内容脚本不得读取或发送评论、商品卡和页面房间指标，录屏继续由本机服务正常完成。
- 开启总开关后，评论、商品卡和房间公开指标分别独立选择，至少选择一项。
- 未选择的类型不得借其他事件间接读取：未选评论时房间快照中的可见评论数量为未知；未选商品卡时商品卡可见状态为未知。
- 采集选项在扩展侧只保存在 `chrome.storage.session`，不进入 `storage.local` 或 `storage.sync`；Chrome 官方定义插件重新加载、更新或浏览器重启会清空该内存区。为恢复当前活动任务，本机私有任务状态额外保存用户本次明确开启的评论、商品卡和页面指标三个布尔开关；不保存浏览器会话、评论正文、商品正文或 DOM，不得据此扩大原采集范围。任务结束后这些布尔值只作为本次任务设置留痕，不自动启动下一次采集。
- 只要任一页面采集项启用，采集器就必须记录开始、选项变化、页面刷新、停止和可观察的中断状态，并附当时实际启用的三个布尔开关。
- 录制任务创建成功后，侧边栏立即通知同一直播间内容脚本启用页面持续播放；内容脚本仍每三秒核对活动任务作为消息未送达或页面稍后暂停时的兜底。插件重新加载造成旧内容脚本上下文失效时，侧边栏先精确核对当前直播间并探测页面助手；只有同一页面没有可用接收者，才重新注入扩展包内固定的页面助手，再发送本次启动消息。该保护独立于互动记录开关，不是一个额外设置。页面已因长时间无操作进入节能暂停时，只查找同时满足明确暂停文案与精确“继续播放”标签的可见控制，触发后验证暂停层是否消失，最多尝试两次。消息中的直播间与当前页面不一致时必须拒绝。该动作不使用外部浏览器控制，不切换或聚焦标签页，不模拟鼠标、键盘或周期活跃，也不得点击“使用客户端免弹窗”等其他控制。互动记录已开启时，分别记录 `playback_paused`、`playback_resume_requested`、`playback_resumed` 或 `playback_resume_failed`；互动记录关闭时不创建采集会话，也不发送这些状态事件。暂停与恢复失败只影响页面可见增强的完整性判断，不代表无浏览器媒体录制暂停。
- Chrome 插件全局只绑定一个活动录制直播间。录制中切到另一个直播间时，当前新页面不得启动采集或把事件发送给原任务；原页面仍存在时只继续原房间采集，原页面关闭或跳走时记录停止／中断。无浏览器多直播流录制不启用本页面增强。

## 直播事件输入

每批请求包含一个 `collector_session_id` 和 `events`。同一任务内 `(collector_session_id, sequence)` 唯一，重发只能返回重复，不得重复落账。

支持原有四类事件；商品快照扩展及 `product_detail`、`product_list_item` 按 [商品资料采集合同](product-collection-contract.md) 校验。列表中的商品及“讲解中”标注不能解释为实际弹窗；只有来源被确认时才关联稍后打开的详情：

| event_type | 必需可见字段 | 边界 |
| --- | --- | --- |
| `comment_visible` | 页面已脱敏昵称、评论文字、观察方式 | 不保存头像、主页链接、真实 ID；周期快照只标首次观察 |
| `product_state` | 是否可见、当前商品标题、展示价、变化类型 | 场控点击后实际显示才记出现；连续两次扫描不可见才记暂时隐藏；暂时不可见不等于下架 |
| `room_snapshot` | 在线人数、点赞累计值、带货标记、购物车数量或页面榜单值 | 都是观察时瞬时值；缺失保持未知，不补 0；带货标记与购物车数量不等于当前商品弹窗 |
| `collector_status` | `started`、`stopped`、`page_reloaded`、`options_changed`、`playback_paused`、`playback_resume_requested`、`playback_resumed`、`playback_resume_failed` 或失败原因，以及三个实际启用项 | 互动记录开启时，页面刷新、选项变化、节能暂停、恢复请求、成功或失败必须留痕，不把缺口伪装成连续采集；全部关闭时不启动采集器，也不为页面持续播放保护单独创建事件 |

单条事件还需包含非负整数 `sequence`、正数 `observed_at_epoch_ms` 和与当前任务相同的规范直播间 URL。文本字段限制长度；服务拒绝额外字段、控制字符、请求头、Cookie、令牌、任意 URL 和嵌套原始 DOM。唯一 URL 例外为新版商品合同中单独校验的公开商品链接与受限图片链接；其他字段继续禁止 URL。

## 本机服务落账

- 服务仍只监听 `127.0.0.1` 的受限候选端口，事件入口继续要求与实际端口和扩展身份匹配的短时会话或本机长期恢复令牌。
- 无浏览器房间轮询直接写入当前独立场次目录 `data/room_metrics.jsonl`；可选页面增强先在私有 SQLite 中按唯一键幂等落账，再只把本次录制窗口事件写入同一场次的 `data/visible_page_events.jsonl`。证据编译器可读取两者并按录屏偏移归一；同房历史场次不得被重新导出到新场次文件。
- 事件文件只使用任务相对数据，不写浏览器配置、接口密钥或平台签名地址。
- 任务重启、页面刷新、浏览器关闭和采集器停止分别留状态事件；没有事件的时段保持未知。

## 转写授权（不属于当前插件采集阶段）

Doubao Lite 是外部云处理。只有在使用者明确允许把指定音频上传火山方舟后才可运行。`ARK_API_KEY` 与模型 Endpoint 只从运行参数或环境读取，不进入 Skill、日志、发布包或转写交付。授权只覆盖当次明确指定媒体，不自动扩大到整场录屏、评论文件或浏览器数据。

## 协同分析等级（不属于当前插件采集阶段）

| 等级 | 可写判断 |
| --- | --- |
| `DIRECT_RESPONSE` | 主播点名或复述了可见评论的独特内容，且校准后的先后关系成立 |
| `GROUP_RESPONSE` | 多条同题评论与主播群体回答高度匹配，但不能绑定某一条评论 |
| `POSSIBLE_RELATION` | 主题或时间接近，证据不足以排除主播原计划话术 |
| `NOT_OBSERVED_IN_WINDOW` | 在明确观察窗口内未找到对应回答；不能外推为整场忽略 |
| `UNAVAILABLE` | 评论、转写、商品状态或时间校准缺失，不生成互动结论 |

商品弹窗协同另记：切换前预热、切换同窗承接、切换后补讲、口播价格是否可核验、权益是否一致和行动指令。在线人数、点赞和榜单只作为背景轨迹，不用于证明弹窗或话术造成成交、涨跌或转化。

## 后续协同交付（不属于当前插件采集阶段）

成熟交付至少包含：

- 直播事件 JSONL、采集来源与完整性状态；
- 带录屏偏移的机器转写 JSONL、SRT 和模型／授权清单；
- 评论—主播—商品弹窗证据表；
- 可点击的协同时间轴或带时间锚点报告；
- 采样间隔、页面刷新、录屏偏差、机器转写和未人工复核边界。

当前插件采集阶段交付原始页面事件 JSONL、采集来源、启用项、采集状态和完整性边界。0.21.5 同时提供同一批记录的可阅读 Markdown 与 CSV，不增加采集范围。没有使用者后续明确指令，不生成转写、协同分析证据表、时间轴或分析结论。

## 0.21.5 可阅读互动交付

每场启用了互动或已收到事件的录制，在结束时生成 `05_直播互动/直播互动记录.md`、`直播互动记录.csv`、`完整性.json`，并在 `02_录屏说明与完整性.md` 加入口。原 `data/visible_page_events.jsonl` 仍是结构化依据。未启用且无事件时不生成空互动包；启用但没有事件时明确警告，不能因视频成功而称互动完整。

计数分别呈现评论、商品卡状态与页面指标；商品卡状态次数不等于商品数。Markdown/CSV 保留观察时间、任务时钟偏移、窗口内外、脱敏昵称、原评论及状态说明，CSV 另含事件与采集会话编号。基线评论不标作此时新发布，原始 JSONL 不做表格防公式转义，派生 CSV 对公式前缀做保护。

仅物化当前任务启动时点后的已校验事件，历史房间数据不混入；停止后合法尾批会重新生成可阅读文件。启用项表示导出时配置，过程中的配置变化仍以事件为准。窗口外记录单独计数；偏移是任务开始的本机时钟而非逐帧视频秒数，仍需后续校准。旧场次不自动重写或迁移。

## 验收分层

1. 合同和合成测试：事件校验、去重、时间窗口、未知值、敏感字段拒绝和证据等级。
2. 本机服务测试：已鉴权批量接收、重复重发、错误任务、跨直播间、超长文本和停止后尾批处理。
3. 真实页面短测：评论新增、场控商品卡出现／隐藏／切换、人数变化、页面刷新与录屏手停。
4. 延迟校准：比较浏览器播放器与直接直播流偏差，记录误差范围；未通过前不得宣称逐帧精确。
5. 长时与页面变化：持续运行、评论高频、商品频繁切换和 DOM 结构变化；低层测试不能替代该层。
