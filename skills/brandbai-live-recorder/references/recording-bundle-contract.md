# 直播记录统一资料包 · 0.22.1

只改变新录制的交付分类和浏览器显示名称，不扩大采集，不迁移历史文件。同时遵循直播互动、商品采集、商品身份及浏览器交付合同；本节替代旧版的混合互动表及额外录制商品包入口。

## 一个录制任务，一个 ZIP

- `00_直播记录说明.md`：阅读入口。
- `03_直播录屏/`：视频与源文件；既有路径和媒体台账不改写。
- `05_直播互动/`：为兼容保留目录及文件名，表格正文只含评论和采集状态。`完整性.json` v2 保留全类型计数，`classified_sections` 表示已分类。
- `06_弹窗商品/`：本场弹窗商品概览、弹窗时间记录（Markdown/CSV）、结构化记录、缩略图和下载清单。
- `07_直播指标/`：页面瞬时人数、点赞及榜单。无浏览器轮询仍在 data/room_metrics.jsonl，不与页面来源混写。
- 原 data 台账与 `04_商品资料.md` 兼容视图保留；04 明确为页面原始观察，不是完整商品包。

“同步记录直播信息”沿用原来的三个独立授权开关，默认关闭。录制结果不再显示额外商品下载按钮；独立商品详情、SKU、目录、评价下载保持原流程，不自动打开商品。旧版 API 保留兼容，不由新版录制结果触发。

## 多卡片与商品身份

只用 product_state 构建弹窗记录。product_list_item、product_detail 不推成弹窗；card_observation_id 是单次观察引用，不是商品 ID。

公开商品 URL 中明确的商品 ID 可以关联。未知 ID 时，仅在同一场次、同一房间内用标题、店铺和同一缩略图整理“同外观卡片观察组”；保持 product_id=null，不作为已确认商品去重，更不能跨包合并。证据不足时逐次保留，不凭标题推断。组号不是 1 号/2 号链接。已知不同商品 ID 不合并。

每次可见、信息变化、暂不可见和恢复可见均保留原时间、价格、权益、窗口标记及事件编号；基线只表示开始观察时已可见。隐藏不表示下架，恢复不证明又发生一次场控操作。采集中断或重接清除“上一张卡片”的隐藏关联；时间是任务墙钟而非精确视频秒数。

每观察组最多保存一张已观察的公开卡片缩略图，相同 URL 共用文件。重用原图片访问白名单、DNS/重定向检查，不带 Cookie、不访问隐藏接口。结束整理阶段最多 200 个新图片请求，目标总预算 30 秒、单图 5 秒/2 MiB，失败或上限单列，保留已取得的视频及文字。网络超时依赖主机网络栈，不承诺所有主机精确到秒。尾批复用已保存图片，不在事件写入锁内请求网络；未取得图片保留部分状态。

## 显示命名

浏览器 ZIP：`抖音_已确认直播间名称_直播记录_YYYY-MM-DD_HH-mm-ss.zip`。

从该冻结场次 data/export_*.json 读取实际公开主播名，不读后来切换的标签页或最新任务。未确认或名字冲突用中性 `抖音_直播记录_时间.zip`，不显示“待核”和内部编码。时间优先用该场任务开始时间，否则用交付创建时间；媒体实际开始时点另外保留。房间名最多 32 字符，只做安全文件名处理。

浏览器同名保留新副本，ZIP 注册表和私有工作目录仍使用唯一 ID。房间、场次和观察编码保留在 JSON；名字不作为合并键。0.22.6 独立商品/目录/评价采用简洁命名，见导出命名合同；用户已下载的文件不重命名、不覆盖。

## 验收边界

合成测试覆盖重复快照、多商品、未知/已知 ID、隐藏/恢复/重接、列表详情排除、原始数据不改、窗口标记、CSV 公式保护、缩略图去重/失败/尾批、冻结场次命名和权限范围。真实长时多弹窗仍需页面验收，不能用合成测试宣称已覆盖所有页面行为。
