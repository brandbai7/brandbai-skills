# BrandBAI 直播录屏 Skill｜能力说明

**把直播、商品和买家反馈，整理成可保存、可查找、可供后续分析的资料。**

适用于品牌直播复盘、公开直播间研究、商品资料整理与买家反馈研究。既可以在支持 Skill 的 AI 工具中发起录制，也可以配合“BrandBAI 直播录屏助手”浏览器插件保存页面资料。

## 可以做什么

| 能力 | 具体用途 | 使用方式 |
| --- | --- | --- |
| 直播录制 | 按设定时长保存公开抖音直播，可选画质、单个视频或分段视频；支持多个不同直播间独立录制 | Skill 可直接调用；插件可控制当前直播间 |
| 直播互动记录 | 保存观察到的直播评论、弹窗商品卡与出现／变化记录，方便回看主播在什么时间讲什么、观众在问什么 | 插件中主动开启，原直播页需持续更新 |
| 在线人数记录 | 按时间保存可取得的在线人数、点赞等公开指标，供后续对照直播内容 | 录制时保存可取得的指标；页面指标可选 |
| 本场商品目录 | 保存“几号链接”、商品名称、展示价格、缩略图和可见讲解标注，先了解直播间整体卖什么 | 插件独立下载，无需录屏 |
| 单商品资料 | 保存主图、详情图、公开参数，以及页面可选规格的价格与对应图片 | 打开商品后由插件独立下载 |
| 买家评价 | 保存当前筛选与排序下的评价文字、所购规格、已显示追评和商家回复、附图数量 | 在同一商品打开评价后独立下载 |
| 后续转写与对照 | 指定已有录屏另行转写，并整理话术、评论和商品事件的对照证据 | 另行发起；云端转写须单独同意上传 |

直播评论是直播中观众发言；买家评价是商品历史购买反馈，两类资料分别保存，不混在一起。

## 典型使用流程

**先看整场，再看重点，最后做分析。**

1. 录制一段直播，按需同时记录评论、弹窗商品和在线人数。
2. 保存本场商品目录，了解商品与链接编号。
3. 打开重点商品，分别保存图片规格与买家评价。
4. 将视频、商品与反馈资料交给后续分析流程，开展直播复盘、商品研究或内容研究。

以上步骤可以单独使用：不录屏也能下载商品，不下载图片也能保存评价。资料收集结束后不会擅自继续转写、上传或生成经营结论。

## 会收到什么

- **直播记录**：视频、录制说明，以及按所选范围保存的评论、弹窗商品和人数记录。
- **商品目录**：可阅读目录、商品缩略图、结构化清单。
- **单商品资料**：图片文件、规格与价格对应、公开参数、商品身份及完整性说明。
- **买家评价**：可用 Excel 等表格软件打开的 CSV、逐条结构化记录与说明。

浏览器版每次任务一个 ZIP，默认保存到浏览器下载位置，无需单独设置文件夹；同名文件保留新副本。Skill 无浏览器录制按独立场次目录保存。

商品资料和评价包保留共同的商品身份字段。已取得真实商品 ID 时，可用于跨次关联；没有 ID 时不凭名称或几号链接猜测合并。文件名称使用可读的直播间／商品名称与时间，不堆叠内部编码。

## 常用设置

- 直播默认标清、30 分钟、不分段，可调整总时长、画质及分段方式。
- 商品目录每轮最多新增 100 条，未读完可继续；不会逐个打开全部商品详情。
- 单商品读取最多 40 个页面可选规格组合、200 张图片；超出限制或未收齐会明确说明。
- 评价默认目标 200 条，可选 50／500 条。50 条每轮最多 3 分钟，200／500 条最多 10 分钟；符合原页面条件时可手动继续。

目标数量是本次希望取得的数量，不是保证数量；每份结果会说明实际取得多少、是否完整以及为什么结束。

## 使用时需要注意

**页面资料依赖网页实际展示。** 互动采集建议保持原直播页前台，不要在其他设备或窗口以同账号进入直播间。关闭插件侧栏不主动停止任务；原网页关闭、冻结或停止更新时，互动可能缺失。评价页切到后台会先等待返回，不保证后台持续读取。

**在线人数不等于进房或留存。** 它是某个时点同时在线的数量，不能直接作为独立访客、进房人数或留存率。

**并非所有媒体都能下载。** 商品视频、评价图片与评价视频目前不下载；评价附图只记数量，商品图中文字不自动转成文字。弹窗商品卡不是完整商品资料。

**价格、规格与评价有时间边界。** 价格以采集时页面展示为准；历史评价中的规格不一定是当前在售规格。页面未展示规格，不会直接判断为只有一个 SKU。

**下载与分析分开。** 不自动获取成交额、订单或后台私有数据，不提供销售结果或转化归因保证。只处理有权保存的公开内容，不绕过登录、验证码或访问限制，不购买、不发评论，不采集收货和支付信息。
